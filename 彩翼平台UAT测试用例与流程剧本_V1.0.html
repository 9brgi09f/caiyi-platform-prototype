1. 使用说明

1.1 执行规则

  1. 每条用例执行后，在“执行记录”中填写：实际结果、通过/失败/阻塞、截图或业务单据编号、缺陷编号。
  2. 所有新增测试数据必须带 QA-TEST- 前缀或“仅供测试、非真实”标识；不得使用真实身份证、真实营业执照、真实发票或真实收款账户。
  3. 遇到外部系统步骤，仅验证平台是否正确生成待处理状态、接口状态或回传结果展示；不得向真实支付、银行、金蝶或税务系统提交生产业务。
  4. 不通过直接修改 URL、浏览器控制台、接口参数等方式绕过页面或服务端校验。
  5. 不操作归属不明、可能关联真实业务的智能体、结算单、提现单、发票或账户。

1.2 结果定义

状态定义
通过实际结果与预期结果完全一致，且无异常报错。
失败功能可操作，但实际结果与预期不一致。
阻塞因系统错误、缺少测试数据、外部环境或已知缺陷，无法继续执行。
不适用当前环境未部署该模块、角色无测试入口或经项目负责人确认不在本轮范围。

UAT-REG-001 个人用户公开注册与审核通过

项目内容
优先级P0
角色新注册个人用户、平台运营
前置条件准备未注册手机号、QA-TEST- 姓名及仅供测试的实名信息；运营账号可访问注册审核。

3. 提交申请，记录申请编号或截图。

3. 提交后状态为“待审核”。
4. 审核通过后个人账号激活，可登录并显示个人身份。
5. 用户收到审核通过/体验权益相关消息；市场或详情页可看到免费体验状态。
外部依赖短信、实名核验如为模拟，仅验证页面状态与提示。

UAT-OPS-005 机构运营规则的生效范围、版本与历史快照

4. 历史业务可追溯当时采用的规则版本/快照，规则详情与实际结果一致。

UAT-OPS-007 机构运营规则异常处理、冲突校验与回滚

项目内容
优先级P1
角色平台运营管理员、规则查看账号

4. 停用、撤销或回滚后仅对后续适用范围按规则生效，历史业务快照保持可追溯；回滚原因、操作人和时间被审计记录。
