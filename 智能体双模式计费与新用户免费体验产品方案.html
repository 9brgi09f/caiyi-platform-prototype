1 背景与目标

平台需要同时适配不同智能体的成本与商业化方式：输出量波动较大的智能体适合按 Token 计费；任务边界稳定、用户容易理解的智能体适合按次计费。同时，首次完成平台注册并获得可用身份的新用户，需要先体验智能体价值，再进入充值和付费调用路径。

本期目标：让开发者可选择合适的收费模式；让用户在调用前明确知道是否扣费；让运营可统一配置新用户免费次数，并可追踪权益消耗。
目标可验证指标
降低首次使用门槛新注册用户可在市场、详情页和调用反馈中识别每个智能体的免费体验剩余次数。
统一收费表达开发者、用户和运营端均明确展示智能体的按 Token或按次收费规则，避免“按量”等模糊表述。
保证权益与扣费正确每次成功调用只发生一次权益扣减或一次付费扣减；重复请求、失败调用不得重复扣费。
支持经营分析免费调用、付费调用、平台成本和后续转化可按用户、智能体、时间维度查询。

2 适用范围与角色

对象本期职责关键边界
首次完成平台注册的新用户个人用户免审开通后、企业/机构用户审核通过后，获得免费体验资格并可浏览、调用智能体、查看权益与消费记录。权益绑定平台注册人对应的个人账号；新增机构身份、切换角色或同一人申请多个机构类型均不会重复发放。
开发者创建、编辑智能体时选择按 Token或按次计费，并完成价格与用量配置。免费体验不向用户收费；本期原型不将免费调用纳入开发者分成。
平台运营配置后续新注册用户的每智能体免费次数，并查询用户权益消耗。规则调整只影响调整后新注册用户，已注册用户保留注册时获得的规则快照。
财务与结算按正式账务口径处理付费调用、开发者结算和发票。免费调用金额为 0，不进入用户开票和开发者分成；平台承担对应算力成本。
范围说明：个人用户在免审开通后获得资格；采购单位、供应商、代理机构、开发者等企业/机构用户在审核通过并开通机构主账号身份后获得资格。权益始终绑定申请人的平台个人账号，不能因后续新增机构身份而重复发放。

3 智能体双模式计费设计

3.1 计费模式

模式适用场景开发者配置用户侧展示
按 Token 计费输出长度、推理复杂度或上下文波动较大的智能体。Token → 彩豆换算率、单次预估 Token 区间、单次 Token 熔断上限。“按实际 Token 用量计费”，在调用前展示预估区间；最终以成功调用的实际 Token 为准。
按次计费任务输出相对稳定、适合用单次价格表达价值的智能体。固定每次价格、单次预估 Token、单次 Token 熔断上限。“{价格} 彩豆/次”，调用成功后扣除固定价格。

3.2 配置与校验规则

规则产品要求
计费方式切换创建和编辑页均支持两种模式；编辑已上架智能体时，变更随审核流程生效，审核期间继续使用线上已生效规则。
价格合法性价格、换算率、预估 Token、熔断上限均须为正数；Token 熔断上限不得小于预估上限。
按次价格风险校验若“每次价格 × 开发者分成比例”低于预估算力成本，则阻止提交并提示开发者调整价格或模型配置。
计费快照每笔成功调用必须记录调用时已生效的计费模式、价格/换算率、分成比例与成本参数，后续规则变更不得回写历史记录。
Token 熔断当累计 Token 达到上限时，服务端应中止后续生成并返回可解释结果；实际使用量按已产生的 Token 记录。

4 新用户免费体验权益

核心规则：新注册用户 × 每个智能体 = 一组一次性免费体验次数。每个智能体独立累计，成功调用优先消耗 1 次；用完后不重置，后续按该智能体当前有效计费规则收费。
规则项规则定义
配置主体平台运营在“计费规则”中统一配置每位后续新注册用户对每个智能体的免费次数。填 0 表示不提供免费体验。
适用条件个人用户在免审开通后适用；企业/机构用户在审核通过、机构主账号身份开通后适用；运营后台首次创建的平台个人账号也按当前规则适用。待审核、已驳回和历史补录账号不发放。
权益归属按“平台个人账号 × 智能体”独立累计；不与机构、角色、设备或浏览器绑定。同一账号后续新增机构身份不重复发放。
初始化时点用户达到适用条件时记录免费次数规则快照；首次成功调用某智能体时，创建该智能体的权益余额记录。也可在获得资格时批量初始化，但需控制智能体规模带来的数据量。
扣减时点仅在调用成功、获得有效结果后扣减 1 次；模型超时、参数校验失败、系统错误或用户取消不得扣减。
用尽后处理余额为 0 时，调用前展示收费规则；成功调用后按当次计费快照扣除彩豆。
成本与结算免费调用的用户金额为 0，算力成本由平台承担；本期不计入开发者分成、不进入用户可开票金额。
规则变更仅作用于规则生效后新注册用户。已注册用户继续按注册时记录的免费次数规则执行，剩余次数不受运营配置修改影响。

5 各端产品交互

5.1 用户端：让用户知道、理解并能验证权益

页面 / 节点展示与交互要求原型状态
注册或审核通过结果页个人用户注册成功、企业/机构审核通过后均提示“新用户体验权益已到账”，说明每个智能体可免费体验 {次数} 次，并提供进入智能体市场的主按钮。机构通过页待补
智能体市场每张智能体卡展示“剩余 N 次”“仅剩 N 次”或“免费体验已用完 · 按计费规则扣费”。已覆盖
智能体详情与调用前明确本次是否消耗免费次数；余额为 0 时明确收费方式。禁止用户在不知情时进入付费调用。已覆盖
调用后反馈免费调用显示已消耗 1 次及剩余次数；付费调用显示实际扣费、计费依据与消费记录入口。原型模拟
消费记录 / 调用详情免费调用标记“免费体验”、金额为 0、不进入待开票范围；详情展示权益扣减、调用 Token 和计费快照。已覆盖
用户首页建议增加权益摘要与“去体验智能体”入口，避免用户只能进入市场后才发现权益。后续优化

5.2 开发者端：可定价、可理解审核边界

创建和编辑智能体提供“按 Token计费 / 按次计费”单选入口，并随选择展示对应字段与测算说明。详情与列表对按次示例展示固定价格，对按 Token 示例展示按实际用量计费。

本期不要求开发者自行配置免费次数，也不在开发者收入中将免费调用包装为收入；正式经营报表可单独展示免费调用量、平台补贴成本和付费转化，避免混淆结算金额。

5.3 运营端：可配置、可查询、可追溯

“规则设置 → 计费规则”中配置免费次数，并清晰标注其适用于后续首次完成平台注册并获得可用身份的新用户。个人账号详情展示按智能体拆分的初始次数、已使用、剩余和最近使用时间。规则保存应生成修改记录。

6 核心数据与调用流程

6.1 建议的数据对象

对象关键字段用途
计费规则版本规则版本、Token 单价、免费次数、启用状态、生效时间、操作人运营配置留痕，并为新注册用户确定适用规则。
智能体计费版本智能体 ID、模式、单价/换算率、Token 预估与上限、审核状态、生效时间保证调用与结算使用正确的计费快照。
用户免费权益个人账号 ID、智能体 ID、初始次数、已用次数、剩余次数、规则版本、最近使用时间支撑市场展示、调用前判断、原子扣减与运营查询。
调用记录调用请求 ID、用户、智能体、结果状态、Token 用量、免费/付费标记、金额、计费快照、时间消费明细、对账、问题追溯和报表统计的唯一依据。
账户流水流水 ID、账户、变动类型、彩豆金额、关联调用 ID、余额、时间仅对付费调用产生扣费流水；免费调用可产生 0 元业务记录但不改余额。

6.2 调用主链路

发起调用生成唯一请求 ID
读取权益与计费快照判断剩余免费次数
执行智能体记录实际 Token 与结果
成功后原子结算扣免费次数或彩豆
返回结果与记录展示剩余次数或扣费明细
实现要求：权益判断、权益扣减/彩豆扣减、调用记录落库必须以请求 ID 做幂等控制。对于并发调用，服务端必须采用事务或条件更新，确保免费余额不会扣成负数，也不会出现同一次调用重复扣减。

7 异常、权限与口径边界

场景处理原则
同一请求重试使用请求 ID 幂等返回原结果或原结算结果，不得二次扣权益或余额。
调用执行失败不扣免费次数、不扣彩豆；保留失败记录、错误码与耗时，便于排障和成本分析。
权益余额与页面不一致详情页和结算以服务端实时余额为准；前端只作展示，不可凭前端变量决定最终扣减。
免费次数与计费规则变更已有用户按权益记录中的规则快照执行；新用户按新规则初始化。历史调用按调用快照展示与结算。
彩豆余额不足免费次数已用尽且余额不足时，在调用前阻止请求并引导充值；不得先调用后发现扣款失败。
智能体下架或审核中不可发起新调用；已产生的调用记录与权益记录保留，不因下架删除。
个人账号加入或退出机构个人免费权益不随机构成员关系迁移、复制或删除；机构资源与个人权益必须隔离。

8 验收标准

编号验收标准
AC01开发者创建和编辑智能体均可在按 Token和按次计费之间选择，且各自配置项、校验规则和说明正确切换。
AC02按 Token智能体按实际成功调用的 Token 用量计费；按次智能体成功调用后按固定价格计费；两种模式均记录调用时计费快照。
AC03运营可配置每位后续首次完成平台注册并获得可用身份的新用户对每个智能体的免费次数，0 表示不提供；保存后产生可查询的规则版本或修改记录。
AC04个人用户免审开通后、企业/机构用户审核通过后，对每个智能体获得独立的一次性免费次数；成功调用优先消耗 1 次，用完不重置。同一账号后续新增机构身份不重复发放。
AC05用户注册成功页、智能体市场、详情页与调用反馈能准确展示免费权益状态；余额为 0 时在调用前明确收费规则。
AC06免费调用金额为 0，消费记录明确标记免费体验且不进入待开票范围；免费调用不产生用户扣费流水和开发者分成。
AC07运营端个人账号详情可查看每个智能体的初始、已用、剩余免费次数及最近使用时间。
AC08系统对相同请求 ID 的重复调用保持幂等；失败调用不扣权益或彩豆；并发调用不会产生权益负数或重复扣款。
AC09运营修改免费次数仅影响修改后注册的个人账号；已注册用户的免费权益和历史调用明细不被回写。
AC10研发可按用户、智能体、时间区分免费与付费调用，并统计免费调用次数、平台成本、付费转化和收入。

9 后续迭代建议

方向建议内容优先级
权益运营支持指定智能体、指定渠道或指定人群的体验包；明确叠加、覆盖、有效期和回收规则。P1
经营看板按智能体查看免费体验领取率、调用率、用尽率、首充率、免费成本与付费收入。P1
开发者分析在开发者端分开呈现免费调用量、平台补贴成本、付费调用收入与实际结算，避免收入误解。P1
调用详情已补齐免费体验调用详情中的免费标记、权益扣减变化、Token 用量与计费快照；付费调用详情可继续补齐失败原因与重试说明。P1
风控与限额增加用户、智能体、IP、设备等维度的调用频控；防止批量注册和免费权益滥用。P1

说明：当前静态原型中的余额、权益与扣减均为演示数据。正式上线前应完成服务端账户、调用、计费、幂等、审计、风控和监控能力建设。
