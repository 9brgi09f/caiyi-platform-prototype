# 彩翼平台单位彩豆管理与授权消费产品方案

> **版本**：V1.7
> **日期**：2026-08-27
> **覆盖范围**：单位彩豆共有账户、充值与付款、消费记录、开票口径
> **前置方案**：[机构主子账号与岗位权限产品方案](../机构主子账号与岗位权限产品方案.html)

---

## 1. 背景与结论

机构客户需要让员工共同使用智能体。V1.6 曾采用「企业共享池 + 逐成员配置使用额度 + 个人优先企业兜底」的模型，实施评估中发现三个问题：一是企业内部同时存在个人彩豆与单位彩豆两套余额，成员和财务都要区分来源，界面与账本复杂度高；二是额度制要求主账号为每个成员逐一配置并持续维护，机构管理成本大于风险收益；三是「资格 / 额度 / 权限」三层控制含义重叠，容易产生互相矛盾的状态。

### 1.1 产品结论

采用 **单位彩豆全员共有 + 菜单权限治理**：企业身份下只有一个彩豆账户，属于机构；成员能做什么由岗位菜单权限决定，不再设置成员额度。

```text
有充值权限的成员充值
  → 彩豆计入单位彩豆账户（机构资产）
  → 有智能体市场权限的成员即可调用消费
  → 每笔消费实时扣减单位彩豆并记录消费人
  → 有消费记录菜单权限的成员可查看全公司消费记录
```

### 1.2 与 V1.6 的取舍

| 维度 | V1.6（已废弃） | V1.7（本版） |
| --- | --- | --- |
| 账户结构 | 个人彩豆 + 企业共享池双轨 | 单位彩豆单一账户 |
| 消费授权 | 逐成员配置使用额度，初始 0 | 有智能体市场权限即可消费 |
| 扣减规则 | 个人优先、企业兜底、按来源拆分 | 单一来源，直接扣减单位彩豆 |
| 充值 | 个人充值 / 企业充值两条链路 | 单一充值链路，付款方式可选 |
| 管理成本 | 主账号需为每人配额度并维护 | 只需分配岗位权限 |
| 风险控制 | 额度上限 | 权限边界 + 余额预警 + 全公司消费可查 |

### 1.3 方案价值

| 目标 | 方案如何实现 |
| --- | --- |
| 企业资产归属清晰 | 彩豆始终在机构账户，不划转、不形成成员个人余额。 |
| 使用门槛低 | 授予岗位即可使用，无需逐人配额度，符合"公司买、员工用"的真实预期。 |
| 责任可追溯 | 每笔消费记录消费人、智能体、调用状态与扣减前后余额。 |
| 财务口径简单 | 单账户单来源，充值与消费两个税务口径独立累计，无混合来源拆分。 |
| 权限边界清晰 | 充值、彩豆管理、消费记录与发票能力分别由对应菜单权限控制。 |

## 2. 目标、范围与边界

### 2.1 本期目标与纳入能力

**目标**：让机构充值的彩豆能被授权成员直接使用，同时保证资产归属、消费追溯与开票口径清晰。

| 纳入能力 | 说明 |
| --- | --- |
| 单位彩豆账户 | 机构唯一彩豆账户，全体授权成员共用。 |
| 充值与付款 | 有充值菜单权限的成员均可充值；付款可选个人支付或机构对公账户。 |
| 消费与扣减 | 有智能体市场权限的成员调用智能体，实时扣减单位彩豆。 |
| 彩豆管理 | 余额、本月充值/消费/成功调用、余额预警与全部变动明细。 |
| 余额预警 | 平台统一默认阈值，企业不可自行设置。 |
| 充值记录范围 | 有充值菜单权限即可查看全公司充值记录。 |
| 消费记录范围 | 有消费记录菜单权限的成员可查看全公司消费记录并按成员筛选。 |
| 发票能力 | 有发票菜单权限即可对全公司充值与消费申请开票。 |

### 2.2 明确不在本期范围

1. 成员额度、部门预算、单笔消费上限等额度类控制；
2. 企业充值退款与已充值彩豆的回收；
3. 成员离职或停用后的账户处置（单位彩豆归机构，不涉及成员余额，但流程仍需另行定义）；
4. 消费的审批流（先消费后追溯，不做事前审批）。

> 取消额度制后，"回收成员额度"与"额度审批"两类需求随之消失。若后续机构反馈需要事前控制，优先评估**部门预算**而非恢复逐人额度。

### 2.3 个人用户端不受影响

「共有」仅在**企业身份工作台**内生效。个人用户（注册时选择"个人用户"的身份）仍是独立的个人彩豆账户，自行充值、自行消费、自行开票，与任何机构账户互不共享。同一手机号同时拥有个人身份与机构成员身份时，两个工作台的余额、记录与发票完全隔离。

## 3. 核心账务原则

1. **资产归属唯一**：企业身份下的彩豆归机构，不因成员使用而转移归属；
2. **消费必有主体**：每笔扣减都必须记录发起调用的成员与调用单，不存在"机构匿名消费"；
3. **消费记录全员可见**：具备消费记录菜单权限的成员可查看全公司消费记录，账务与消费记录均不按成员拆分可见范围；
4. **失败不产生扣费**（待研发确认，见 12.3）：调用失败的记录保留，消费金额为 0，余额不变。

## 4. 账户、余额与扣减模型

### 4.1 账户定义

| 账户 | 所有者 | 资金来源 | 使用者 | 余额展示 |
| --- | --- | --- | --- | --- |
| 单位彩豆账户 | 机构 | 有充值菜单权限的成员充值（个人支付或机构对公账户付款） | 有智能体市场权限的机构成员 | 「彩豆管理」页展示机构余额；无该菜单权限的成员不展示余额 |
| 个人彩豆账户 | 平台个人账号 | 个人身份下本人充值 | 账号本人（个人工作台内） | 仅个人工作台展示，见 2.3 |

企业身份工作台内**不再出现"个人彩豆"概念**，也不存在成员名下的企业余额。

### 4.2 扣减规则

设一次调用应消费 `C` 彩豆，单位彩豆余额为 `E`：

```text
调用可执行条件：E >= C
扣减额 = C
扣减后余额 = E - C
```

无来源拆分、无额度校验、无优先级顺序。余额不足时调用被拒绝并提示充值（提示不携带跳转入口，见 9.3）。

### 4.3 消费示例

| 项目 | 数值 |
| --- | ---: |
| 本次调用消费 | 195.60 彩豆 |
| 对应金额 | ¥195.60 |
| 扣前单位彩豆 | 17,986.15 彩豆 |
| 扣后单位彩豆 | 17,790.55 彩豆 |

生成一笔消费单，记录消费人、智能体、计费方式、调用渠道、调用状态与扣减前后余额；开票由具备发票权限的成员按整笔金额申请。

### 4.4 汇率与计量

充值比例由运营规则统一配置；本期原型按 **1 元 = 1 彩豆** 演示，最终以运营配置为准。消费彩豆与对应金额按同一比例换算展示，界面只展示彩豆与对应金额，不做双单位并列。

## 5. 功能设计

### 5.1 彩豆管理

机构资产视图，由 `balance-view` 控制。

| 区块 | 内容 |
| --- | --- |
| 余额与月度概览 | 单位彩豆余额、本月充值、本月消费、本月成功调用次数 |
| 余额预警 | 平台默认阈值只读展示 + 当前是否触发 |
| 彩豆变动明细 | 充值与消费全部流水，含操作人、业务单号、变动前后余额，可按类型筛选、分页 |

> 「本月成功调用」只统计成功的调用；失败调用出现在消费记录中但不计入该指标，三处统计口径（彩豆管理、消费记录、概览）保持一致。

### 5.2 账户充值

由 `recharge-view` 控制。

1. **充值档位**：固定档位 + 自定义金额，按固定比例实时到账；
2. **付款方式**：同页并列两组——个人支付（微信 / 支付宝 / 个人银行卡）与机构账户支付（机构对公账户）。成员按实际付款方式选择，**充值结果一致**：彩豆均计入单位彩豆账户；
3. **充值记录**：有本菜单权限即可查看**全公司**充值记录，含充值人、金额、购买彩豆、支付方式、支付状态与开票状态；
4. **对公账户维护**仍由 `account-company` 单独控制，与充值权限解耦：可以充值但不能维护对公账户，也可以能维护对公账户但不能充值。

### 5.3 消费与消费记录

1. **消费资格**：有智能体市场权限（`market-view`）即可调用智能体并消费单位彩豆，不设独立的消费权限项，也不设额度；
2. **消费记录范围**：有消费记录菜单权限（`consumption-view`）的成员可查看全公司消费记录并按成员筛选；
3. **列表字段**：消费单号、消费时间、智能体、消费人、消费彩豆、对应金额、扣前彩豆、扣后彩豆、调用状态、开票状态；
4. **详情字段**：概览八项（消费单号、消费时间、智能体、消费人、调用状态、计费方式、调用渠道、开票状态）+ 扣减明细四项（消费彩豆、对应金额、扣前余额、扣后余额）。调用失败时消费彩豆为 0 且提示"调用失败未产生扣费，单位彩豆余额不变"。

> 「计费方式」与「调用渠道」对齐现网运营端消费详情的既有字段。**Token 用量明细（输入/输出 token 数、单价）**现网未提供，若后端已落库建议在详情页展示，是解释扣费金额最直接的字段（见 12.4）。

### 5.4 发票管理

由 `invoice-view` 控制，`invoice-edit` 控制开票信息维护。

1. 有本菜单权限的成员即可对**全公司**的充值订单与消费订单申请开票，不限于本人产生的记录；
2. 充值发票与消费发票口径独立、互不影响，可同时持有；
3. 同一充值订单或消费订单只能整笔申请一次，重复申请被拒绝；
4. 调用失败的消费记录状态为「不可开票」，不占用开票资格。

### 5.5 余额预警

| 项 | 规则 |
| --- | --- |
| 阈值 | 平台统一默认 **500 彩豆**，企业不可自行设置 |
| 触发 | 单位彩豆余额低于阈值 |
| 通知对象 | 机构主账号 + 具备「彩豆管理」权限的成员 |
| 动作 | 站内通知 + 彩豆管理页状态提示 |

> 默认值取"最高充值档一档"量级，触发时的行动指向明确（该充值了）。后续可升级为按近 30 天消费动态计算，本期先用固定值，口径简单、易解释。

## 6. 充值、消费与开票规则

### 6.1 开票口径

| 业务口径 | 资产归属 | 申请主体 | 可开金额来源 | 备注 |
| --- | --- | --- | --- | --- |
| 充值发票 | 机构 | 具备 `invoice-view` 的成员 | 全公司充值订单 | 预付卡口径，税率以财税确认为准；一笔订单仅可申请一次。 |
| 消费发票 | 机构 | 具备 `invoice-view` 的成员 | 全公司消费订单 | 按订单整笔申请；失败订单不可开票。 |

### 6.2 付款账户

机构对公账户维护新增按钮权限 `account-company`（维护机构对公账户），归属「付款账户」菜单；具备「付款账户」菜单权限并被授予该按钮权限的成员可维护机构对公账户，权限编码不随岗位名称变化。

| 账户类型 | 资产归属 | 可维护主体 | 覆盖操作 |
| --- | --- | --- | --- |
| 个人支付方式 | 个人 | 平台个人账号本人 | 微信、支付宝、个人银行卡的绑定、解绑与设为默认。 |
| 机构对公账户 | 机构 | 机构主账号，或具备 `account-company`（维护机构对公账户）权限的成员 | 新增、编辑、删除、设为主账户、设为默认付款账户。 |

1. 不具备 `account-company`（维护机构对公账户）权限的成员，对公账户**仅可在充值时选用**，不可维护；
2. 个人账号不可查看所属机构以外的任何对公账户；
3. 对公账户开户名称必须与机构注册主体一致，不得绑定为个人姓名；
4. 主/子账户与默认付款账户是两个独立维度：前者是银行侧层级，后者决定充值时默认选中，每个机构同时只允许一个默认对公付款账户；
5. 对公账户变更属资金流向变更，须记录操作人、时间与前后值，纳入操作审计。

### 6.3 术语与展示约定

1. 企业身份工作台内不使用"个人彩豆""单位彩豆池""成员额度""资金来源"等 V1.6 术语；余额统称**单位彩豆**；
2. 充值记录、消费记录、发票记录均需保留**操作人**（充值人 / 消费人 / 申请人），不因资产归机构而省略；
3. 消费金额展示为负值（如 −195.60 彩豆 / −¥195.60），充值为正值，方向一目了然。

## 7. 核心流程

### 7.1 充值入账

```text
有充值权限的成员创建充值订单（选择金额与付款方式）
  → 支付渠道返回支付结果
  → 订单状态确认成功
  → 单位彩豆账户原子入账
  → 生成充值账本（记录充值人与付款方式）
  → 产生充值发票可申请资格
  → 触发余额预警状态重算
```

### 7.2 智能体调用与扣减

```text
成员发起调用
  → 校验机构成员状态与智能体使用权限
  → 计算本次应消费金额 C
  → 校验单位彩豆余额是否 >= C
  → 原子扣减单位彩豆
  → 创建消费单（消费人、智能体、计费方式、渠道、调用状态、扣减前后余额）
  → 更新消费可开票金额与余额预警状态
  → 返回调用结果与扣减明细

调用失败分支：
  → 保留消费单，调用状态=失败，消费金额=0，余额不变，开票状态=不可开票
```

### 7.3 开票申请

```text
具备发票权限的成员筛选全公司可开票的充值 / 消费订单
  → 发起开票申请（整笔，不拆分）
  → 占用对应订单的开票资格
  → 财务审核
  → 开具 / 驳回 / 进入外部接口处理状态
  → 更新申请、资格与账本关联状态
  → 保留申请人、订单明细与操作人链路
```

## 8. 关键关联与不可变字段

以下字段不得因页面展示简化而遗漏：

```text
资金归属机构
操作主体（充值人 / 消费人 / 申请人）
机构成员关系与岗位快照
业务单号、调用单号、消费单号、充值订单号、发票申请单号
扣减前余额、扣减额、扣减后余额
智能体、计费方式/版本、调用渠道、调用时间、调用状态
付款方式与付款账户（充值）
对账状态、发票资格状态、外部接口状态
```

取消的字段：资金来源（个人/企业）、个人扣减额、企业扣减额、成员额度前后值。

### 9.2 授权设计注意事项

1. 无对应菜单权限的成员直接访问页面 URL 时，**服务端必须拒绝**；原型仅演示显隐，前端隐藏不等于权限控制；
2. 岗位可自由组合菜单权限，不预设固定角色；示例岗位仅用于演示。

### 9.3 跨菜单跳转约定

各菜单独立授权，页面之间**不设跨菜单跳转按钮**：彩豆管理页不放"立即充值/消费明细"，账户充值页与消费记录页不放"彩豆管理"。原因是任一跳转都需要判断目标菜单权限，收益低于复杂度。余额不足的提示只说明结果，不携带充值入口。

> 概览页的快捷操作是例外（页面主体即入口集合），须按权限过滤后展示。

### 9.4 原型实施顺序（已完成）

1. 菜单合并与彩豆管理页重做；
2. 充值单轨化与付款方式并列；
3. 消费记录范围与消费详情字段；
4. 发票范围与单号体系勾稽；
5. 岗位权限、概览统计与子账号视角。

## 11. 验收标准

| 编号 | 验收标准 |
| --- | --- |
| AC01 | 充值成功后彩豆仅计入机构单位彩豆账户，不形成任何成员名下余额；无论付款方式为个人支付或机构对公账户，入账结果一致。 |
| AC02 | 具备 `market-view` 的成员可调用智能体并扣减单位彩豆，无需额外的消费资格或额度配置；余额不足时调用被拒绝。 |
| AC03 | 每笔消费生成唯一消费单，记录消费人、智能体、计费方式、调用渠道、调用状态与扣减前后余额；扣减前余额 − 消费额 = 扣减后余额。 |
| AC04 | 调用失败的消费单消费金额为 0、余额不变、开票状态为不可开票，且不计入「本月成功调用」。 |
| AC05 | 具备 `recharge-view` 的成员可查看全公司充值记录（含充值人与付款方式）。 |
| AC06 | 具备 `consumption-view` 的成员可查看全公司消费记录并按成员筛选；无此菜单权限的成员无法通过任何界面路径获取消费数据。 |
| AC07 | 具备 `invoice-view` 的成员可对全公司充值与消费订单申请开票；同一订单不得重复申请。 |
| AC08 | 单位彩豆余额低于平台默认阈值时，机构主账号与具备 `balance-view` 的成员收到可识别的通知；阈值企业侧只读。 |
| AC09 | 具备 `payment-view` 与 `account-company`（维护机构对公账户）的成员可新增、编辑、删除及设置机构对公账户；不具备该按钮权限的成员仅可在充值时选用对公账户。 |
| AC10 | 「本月成功调用」在彩豆管理、消费记录、概览三处口径一致。 |
| AC11 | 个人身份工作台的彩豆余额、记录与发票与任何机构账户完全隔离。 |
| AC12 | 本期不提供成员额度、部门预算、充值退款、彩豆回收与消费审批流。 |

## 12. 待财税与业务确认项

以下事项不应由产品假设决定，需在研发实施前形成书面确认：

1. 「充值发票」与「消费发票」是否均为正式业务口径，及各自的税务依据、税率、品目、纳税义务时点与红冲规则；
2. **开票权归属**由消费人改为发票权限岗位后，进项归集与内部审批是否满足财务要求；
3. **调用失败的扣费口径**：失败是否完全不扣费，或按已消耗 token 部分扣费。若为后者，消费详情与演示数据需同步调整；
4. **Token 用量明细**（输入/输出 token 数、单价）后端是否落库、是否对企业暴露；
5. 充值汇率（1 元 = 多少彩豆）的最终配置口径与调整机制；
6. 是否需要按项目、部门或成本中心的辅助核算（当前不做，与部门预算需求相关）；
7. 银行、金蝶、税务系统的接口边界、对账频率、失败重试与人工介入责任人；
8. 机构停用、账号注销后的单位彩豆余额处置规则；
9. **付款账户菜单对无充值权限成员的意义**：该成员仅能提前维护本人银行卡，是否也一并收回该菜单（原型现状为保留）。
