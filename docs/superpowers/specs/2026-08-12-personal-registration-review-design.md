# 个人用户统一注册审核设计

## 目标

将个人用户从“免审开通”调整为与企业/机构共用运营端注册审核队列。个人用户无需营业执照，但仅在运营审核通过后激活个人账号并获得新用户免费体验权益。

## 规则

1. 个人用户提交姓名、身份证号、手机号、密码、验证码和协议后，申请状态为待审核。
2. 个人用户不提交营业执照、组织名称或统一社会信用代码。
3. 运营端注册审核列表显示“个人实名申请”，机构类型显示“个人用户”。
4. 审核通过后激活个人账号；若手机号首次创建平台个人账号，按当时规则获得每个智能体的一次性免费体验次数。
5. 审核驳回后不激活账号、不发放权益；用户可修改实名资料并重新提交。
6. 企业/机构用户保持原有审核链路；审核通过后激活机构身份并按同一新用户规则发放权益。
7. 平台个人账号手机号唯一、机构成员关系、权益按“平台个人账号 × 智能体”累计等既有模型保持不变。

## 页面与数据流

```text
个人注册表单
  → 提交成功页（待审核）
  → 运营端注册审核列表（个人实名申请）
  → 审核详情（实名资料，无营业执照）
  → 通过：个人账号激活 + 权益到账结果页
  → 驳回：修改实名资料并重新提交
```

## 原型覆盖

- 用户端：注册提交结果、审核中、审核通过、审核驳回三种个人状态。
- 运营端：审核列表个人条目、详情页个人资料分支、通过和驳回反馈。
- 文档：注册流程图、账号类型设计方案、计费与免费体验方案、首页摘要均取消“个人免审”口径。

## 边界

- 当前是静态交互原型；实名核验、验证码、审核工作流、权益写入和通知发送均为模拟。
- 不改动已锁定的 `user/login.html`。
- 不新增成员管理、营业执照上传或真实后台服务。
