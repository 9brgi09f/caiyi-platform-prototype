# 彩翼平台企业共享彩豆、授权消费与财务精细管控产品方案

> **版本**：V1.0  
> **日期**：2026-08-18  
> **覆盖范围**：第二期「企业共享彩豆与授权消费」与第三期「财务与精细管控」联动设计  
> **前置方案**：[机构主子账号与岗位权限产品方案](../机构主子账号与岗位权限产品方案.html)

---

## 1. 背景与结论

机构客户需要让员工使用智能体，但企业充值的彩豆既要由多人协同使用，又要明确企业资产归属、实际使用人和可开票金额。若将企业彩豆逐笔划转给子账号，会带来余额回收、离职处置、企业与个人余额混合、开票归属不清等问题，并会显著放大后续财务对账的复杂度。

### 1.1 产品结论

采用 **企业共享彩豆池 + 子账号授权消费**，不建设“主账号向子账号分配企业彩豆余额”的能力。

```text
机构主账号充值
  → 企业共享彩豆池入账（企业资产）
  → 子账号按岗位权限、额度使用
  → 调用优先扣个人彩豆
  → 个人不足时，扣企业共享彩豆
  → 每次消费分别记录个人 / 企业实际扣减额
```

### 1.2 方案价值

| 目标 | 方案如何实现 |
| --- | --- |
| 企业资产不转移 | 企业彩豆始终留在机构共享池，不形成子账号名下的企业余额。 |
| 员工使用可控 | 使用企业彩豆需有对应权限，并受单次、周期额度和企业余额预警约束。 |
| 消费责任可追溯 | 每一笔企业彩豆消费均记录实际调用子账号、岗位、智能体、调用单与扣减金额。 |
| 个人与企业财务清晰 | 个人充值/消费与企业充值/消费独立入账、独立累计可开票金额。 |
| 为三期留足基础 | 资金来源、归属、扣减前后余额、关联订单和发票状态从二期开始沉淀。 |

## 2. 分期目标、范围与边界

### 2.1 第二期：企业共享彩豆与授权消费

**目标**：让企业主账号充值后的共享彩豆，可由具备资格的子账号安全、可追溯地使用。

| 第二期纳入能力 | 说明 |
| --- | --- |
| 企业共享彩豆池 | 企业充值入企业共享池，余额归机构，不转移给成员。 |
| 个人彩豆余额 | 子账号可自行充值，余额归平台个人账号。 |
| 统一调用扣减 | 优先个人后企业的来源拆分扣减；余额不足时中止调用并提示。 |
| 企业彩豆使用权限 | 通过机构岗位授予“使用企业彩豆”操作权限。 |
| 成员消费额度 | 最小实现支持「不限额、单次上限、周期上限」；建议周期按自然月。 |
| 企业余额预警 | 企业共享池低于阈值时通知主账号及具备财务/管理权限的成员。 |
| 个人与企业消费明细 | 以资金来源拆分查看、导出和追溯。 |
| 发票资格基础 | 分别计算个人和企业的充值、消费可开金额及已申请金额。 |

### 2.2 第三期：财务与精细管控

**目标**：基于二期已沉淀的资金、消费与开票数据，支持企业财务核对、经营分析、精细预算与审计。

| 第三期纳入能力 | 说明 |
| --- | --- |
| 财务工作台 | 企业充值、企业消费、可开票金额、待处理差异和预警的汇总视图。 |
| 多维消费分析 | 支持按成员、岗位、部门（预留）、智能体、时间、场景/业务单号汇总。 |
| 开票管理 | 企业/个人充值发票、企业/个人消费发票的资格、申请、审核、开具、作废/红冲状态管理。 |
| 对账与差异处理 | 订单、支付/银行流水、彩豆账本、调用消费、发票申请的关联核对和差异闭环。 |
| 精细额度与预算 | 支持按成员、岗位、部门、智能体配置周期额度、预算与预警策略；审批能力按后续确认范围建设。 |
| 操作审计 | 记录额度策略、权限、阈值、发票、对账差异等关键操作的操作者、前后值和时间。 |
| 外部系统衔接 | 预留银行、金蝶等系统的接口状态与回传结果展示，不在原型或测试中提交真实业务。 |

### 2.3 明确不在本期范围

以下能力不在第二、三期当前范围内，后续另行评估：

1. 企业回收已授权但未消费的企业彩豆；
2. 企业充值退款；
3. 子账号离职或停用后的余额处置。

> 说明：企业共享彩豆不划至成员名下，因此不存在“回收成员名下企业余额”的问题。个人彩豆的归属、退款及成员离职后的账号处理需在后续专项规则中定义。

## 3. 前置能力与核心原则

### 3.1 复用第一期账号与权限能力

第二、三期建立在“平台个人账号—机构成员关系—机构岗位—操作权限”模型之上：

```text
平台个人账号（手机号唯一）
  ├─ 个人彩豆账户（个人资产）
  └─ 一个或多个机构成员关系
       └─ 机构岗位（菜单权限 + 操作权限）
            └─ 企业共享彩豆使用、财务、发票、额度管理等权限

机构主账号
  └─ 企业共享彩豆账户（企业资产）
```

- 主账号默认拥有机构全部权限；
- 子账号能否使用企业彩豆，由岗位的操作权限决定；
- 仅具有菜单可见权限不足以调用或管理企业资金，服务端必须校验操作权限、成员状态和额度；
- 已停用成员不得调用机构智能体或使用企业共享彩豆。

### 3.2 四项账务原则

1. **资金来源不可丢失**：任何余额、消费、开票记录必须标记为个人或企业来源。  
2. **资产归属不可混淆**：个人彩豆归个人；企业共享彩豆归机构；可用资格不等于资产所有权。  
3. **调用扣减可复算**：每次调用保存定价版本、扣减顺序、扣减前后余额和来源拆分金额。  
4. **开票资格不可重复占用**：同一笔充值或同一笔消费金额，只能按规定来源进入一次对应的开票申请。

## 4. 账户、余额与扣减模型

### 4.1 账户定义

| 账户 | 所有者 | 资金来源 | 使用者 | 余额展示 |
| --- | --- | --- | --- | --- |
| 个人彩豆账户 | 平台个人账号 | 子账号本人充值、后续平台活动赠送（如有） | 账号本人 | 子账号个人余额 |
| 企业共享彩豆账户 | 机构 | 机构主账号或有充值权限成员代表机构充值 | 获授权且未超额度的机构成员 | 企业共享余额；成员侧仅展示可用资格/额度，不展示为个人资产 |

### 4.2 子账号可用金额展示

子账号调用页面应分开呈现，避免把企业资产误理解为个人余额：

```text
个人彩豆：120
企业共享彩豆：可使用（本月剩余额度 80）
本次预计消耗：10
扣减顺序：优先个人彩豆，个人不足时使用企业共享彩豆
```

若成员无企业使用权限、超出额度、企业余额不足或成员已停用，则企业共享彩豆显示为不可用，并说明原因。

### 4.3 标准扣减规则

设一次调用应消费 `C` 彩豆，成员个人余额为 `P`，企业共享池余额为 `E`，成员当前可使用的企业额度为 `L`。

```text
个人扣减 = min(C, P)
企业待扣 = C - 个人扣减
企业实际扣减 = min(企业待扣, E, L)
```

- 若 `个人扣减 + 企业实际扣减 = C`，调用可执行；
- 若小于 `C`，调用不得执行，页面应展示个人余额、企业权限/额度或企业余额的具体不足原因；
- 禁止“先执行调用、后发现余额不足再补扣”的异步透支模式；
- 同一调用在并发下必须通过服务端原子扣减/幂等控制，防止余额被重复扣减。

### 4.4 混合消费示例

| 项目 | 数值 |
| --- | ---: |
| 本次调用总消费 | 10 彩豆 |
| 调用前个人彩豆 | 6 彩豆 |
| 调用前企业共享彩豆 | 200 彩豆 |
| 成员当期企业可用额度 | 40 彩豆 |
| 个人实际扣减 | 6 彩豆 |
| 企业实际扣减 | 4 彩豆 |

本次消费应生成一笔调用消费单，并形成两条来源拆分账本明细：个人消费 6、企业消费 4。两部分金额分别进入个人和企业的消费可开金额，不能合并为一笔不区分来源的开票资格。

## 5. 第二期功能设计

### 5.1 企业共享彩豆池

#### 功能点

- 企业充值订单支付成功后，彩豆计入机构共享彩豆账户；
- 企业共享余额、冻结额（如后续引入）、可用额、累计充值、累计企业消费分开展示；
- 主账号及拥有对应权限的成员可查看企业充值和企业消费明细；
- 充值订单、彩豆入账记录和后续发票申请可相互关联。

#### 余额变动口径

| 场景 | 企业共享池变化 | 记录要求 |
| --- | --- | --- |
| 企业充值支付成功 | 增加 | 关联充值订单、支付结果、入账时间与操作主体。 |
| 子账号调用使用企业彩豆 | 减少 | 关联调用消费单、实际使用人、智能体和企业扣减额。 |
| 调用失败/撤销且确认不计费 | 冲回或不扣减 | 保留原消费单与冲正/失败原因。 |

> 第二期不提供企业充值退款；发生账务异常时仅建设内部异常标记和人工处理入口的预留字段，不自行定义退款流程。

### 5.2 企业彩豆使用权限

在机构岗位权限中新增以下操作权限：

| 权限编码（建议） | 权限名称 | 作用 |
| --- | --- | --- |
| `enterprise_bean.use` | 使用企业彩豆 | 个人余额不足时，允许该成员继续使用企业共享彩豆。 |
| `enterprise_bean.view` | 查看企业消费明细 | 查看符合数据范围的企业消费记录。 |
| `enterprise_bean.quota.manage` | 管理成员额度 | 配置成员的企业使用额度与预警阈值。 |
| `enterprise_bean.recharge` | 企业充值 | 代表机构创建企业充值订单。 |
| `finance.invoice.apply` | 申请企业发票 | 对企业充值或企业消费可开金额发起发票申请。 |
| `finance.reconciliation.view` | 查看企业对账 | 查看企业账本、对账状态与差异。 |

- `enterprise_bean.use` 是调用企业共享池的必要条件；
- 财务相关权限与调用权限独立，允许使用人和开票/对账处理人不同；
- 权限改变后应立即对新请求生效，不追溯改变历史消费归属。

### 5.3 成员额度控制

#### 第二期最小实现

每个机构成员可以配置一条企业彩豆使用额度策略：

| 模式 | 规则 |
| --- | --- |
| 不限额 | 在拥有使用权限且企业余额充足时可使用。 |
| 单次上限 | 单次调用最多使用指定数额的企业彩豆。 |
| 周期上限 | 当前自然月内累计最多使用指定数额的企业彩豆。 |

额度仅限制**企业来源实际扣减额**，不限制成员使用个人彩豆。

#### 第三期扩展

- 按岗位、部门、智能体、业务场景配置额度；
- 支持优先级：成员专属策略 > 岗位策略 > 部门策略 > 机构默认策略；
- 支持预算与阈值预警；
- 审批机制须在业务确认“申请—审批—生效”的责任人、时效和超额处理规则后再建设。

### 5.4 企业余额预警

| 触发条件 | 通知对象 | 第二期动作 | 第三期扩展 |
| --- | --- | --- | --- |
| 企业共享余额低于固定阈值 | 主账号、财务权限、额度管理权限成员 | 站内通知 + 待办提示 | 多级阈值、通知频控、Webhook/IM 通知。 |
| 成员周期额度达到 80% / 100% | 成员本人、主账号或额度管理人 | 站内提醒；达到上限后阻止企业扣减 | 允许申请临时额度、审批流。 |
| 企业调用余额不足 | 实际调用成员 | 明确阻止调用并提示充值/联系管理员 | 支持预算占用与替代支付策略。 |

### 5.5 企业消费明细

企业消费明细是第二期财务衔接的核心页面，至少应支持按时间、成员、智能体和资金来源筛选、分页与导出。

必备字段：

```text
消费单号
调用时间
实际调用子账号 / 平台个人账号
所属机构 / 成员岗位快照
智能体名称、智能体 ID、计费版本
调用/业务单号
本次总消费
个人彩豆扣减额
企业共享彩豆扣减额
企业扣减前余额 / 后余额
成员周期额度前值 / 后值（适用时）
消费状态、冲正关联单
企业消费开票状态
```

## 6. 充值、消费与开票规则

### 6.1 四类资金与开票口径

| 业务口径 | 资产归属 | 申请主体 | 可开金额来源 | 备注 |
| --- | --- | --- | --- | --- |
| 个人充值 | 个人 | 子账号本人 | 个人充值订单 | 一笔充值订单只能进入一次个人充值发票申请。 |
| 企业充值 | 机构 | 主账号或具备发票权限的企业子账号 | 企业充值订单 | 申请人代表机构操作，不改变企业资产归属。 |
| 个人消费 | 个人 | 子账号本人 | 实际个人彩豆扣减额 | 仅累计来源为个人的实际消费。 |
| 企业消费 | 机构 | 主账号或具备发票权限的企业子账号 | 实际企业共享彩豆扣减额 | 可追溯至实际使用成员，但发票主体为企业。 |

### 6.2 充值发票与消费发票的关系

充值发票与消费发票是**两套独立产品口径**。产品需要分别记录资格和状态，不能因“同一笔彩豆”或“同一用户”而自动混合。

必须满足：

1. 一笔充值订单只能申请一次对应的**充值发票**；
2. 一笔消费金额只能按实际资金来源申请一次对应的**消费发票**；
3. 混合消费必须拆分个人与企业部分，不得混开、重复开或重复占用；
4. 具体是否可同时存在充值与消费两个税务口径、税率、发票品目、纳税义务时点及红冲规则，必须由财税确认；平台提供的是可核验、可追溯的数据基础与流程承载能力。

### 6.3 发票资格状态机（建议）

```text
可申请
  → 申请中
  → 财务审核中
  → 已开具

申请中 / 审核中
  → 驳回（恢复可申请金额）

已开具
  → 作废 / 红冲处理中（按财税确认的规则处理）
```

- 发票申请提交时，应对对应可开金额进行“占用”；
- 审核驳回、撤回或失败时，应释放未开具部分的占用；
- 已开具记录不可删除，仅能按确认后的作废/红冲流程建立关联记录；
- 当前范围不定义真实税务系统提交动作，外部接口仅显示待处理、请求、回传或失败状态。

## 7. 第三期财务与精细管控设计

### 7.1 企业财务工作台

面向主账号和财务权限成员，建议展示：

```text
企业共享可用彩豆
本期企业充值 / 企业消费
本期个人消费（仅在有授权的数据范围内展示）
企业消费待开金额、已申请金额、已开具金额
待核对订单数、对账差异数、余额与额度预警数
```

所有指标必须可下钻至订单、账本、调用消费单或发票申请单，不能仅展示汇总数字。

### 7.2 多维消费分析

| 维度 | 二期沉淀字段 | 第三期分析用途 |
| --- | --- | --- |
| 成员 | 机构成员 ID、平台个人账号 ID、成员名称快照 | 识别实际使用人、成员额度使用。 |
| 岗位 | 岗位 ID、岗位名称快照 | 分析职责类型与权限配置影响。 |
| 部门 | 部门 ID、部门名称快照（预留） | 部门成本归集与预算。 |
| 智能体 | 智能体 ID、名称、版本、计费版本 | 分析不同智能体投入与使用效果。 |
| 时间 | 调用、扣减、入账、开票时间 | 月度/季度对账与趋势。 |
| 业务场景 | 业务单号、场景标签（预留） | 按采购项目或业务任务归集成本。 |

### 7.3 对账与差异闭环

建议形成以下关联链路：

```text
充值订单
  ↔ 支付/银行流水（外部回传状态）
  ↔ 彩豆入账账本

调用业务单
  ↔ 消费单
  ↔ 个人 / 企业来源拆分账本
  ↔ 发票资格占用 / 发票申请

对账任务
  ↔ 对账明细
  ↔ 差异单
  ↔ 人工处理记录 / 外部回传结果
```

对账状态建议：`待对账`、`一致`、`存在差异`、`处理中`、`已关闭`。差异单至少记录差异类型、关联单据、发现时间、处理人、处理说明、前后状态与证据附件引用（如有）。

### 7.4 预算、审批与审计

| 能力 | 建议范围 | 关键审计字段 |
| --- | --- | --- |
| 预算 | 机构、部门、岗位、智能体维度的周期预算 | 规则来源、阈值、周期、创建/修改人、启停时间。 |
| 额度 | 成员和组织维度的用量限制 | 上限、已用、剩余、重置周期、例外设置。 |
| 审批 | 仅在确认业务责任与超额处理方式后建设 | 申请人、审批流、意见、节点状态、失效时间。 |
| 操作审计 | 权限、额度、阈值、发票、对账、冲正等关键动作 | 操作人、机构、操作时间、对象、前值、后值、关联单号、IP/终端信息（按安全规范）。 |

## 8. 核心流程

### 8.1 企业充值入账

```text
主账号 / 企业充值权限成员创建充值订单
  → 支付渠道返回支付结果
  → 订单状态确认成功
  → 企业共享彩豆账户原子入账
  → 生成企业充值账本
  → 产生企业充值发票可申请资格
  → 通知相关成员并进入对账待核对范围
```

### 8.2 子账号智能体调用与来源扣减

```text
子账号发起调用
  → 校验机构成员状态、智能体权限与计费参数
  → 计算本次应消费金额
  → 优先校验并扣减个人彩豆
  → 如有剩余：校验企业彩豆使用权限、成员额度、企业余额
  → 原子扣减企业共享彩豆
  → 创建调用消费单与个人/企业来源拆分账本
  → 更新个人/企业消费可开金额、成员额度和预警状态
  → 返回调用结果及扣减明细
```

### 8.3 企业消费开票

```text
主账号 / 发票权限成员筛选企业消费可开金额
  → 发起企业消费发票申请
  → 占用对应企业消费资格
  → 财务审核
  → 开具 / 驳回 / 进入外部接口处理状态
  → 更新申请、资格、账本关联状态
  → 全程保留实际使用子账号与消费明细的追溯链路
```

### 8.4 余额不足或额度不足

```text
调用前校验失败
  → 不执行智能体调用
  → 返回明确原因：个人余额不足 / 无企业使用权限 / 成员额度不足 / 企业余额不足
  → 引导成员使用个人充值或联系有企业充值、额度管理权限的人员
  → 记录必要的失败事件用于运营分析，不生成成功消费单
```

| 发票申请单 | 申请单号、申请主体、资格明细、状态、外部接口状态、开票结果 | 承载申请、审核、开具全流程。 |
| 对账任务/差异单 | 对账周期、对账对象、状态、差异类型、关联单据、处理记录 | 第三期财务闭环。 |
| 操作审计日志 | 操作人、机构、模块、动作、对象、前后值、时间、关联单号 | 关键配置与财务行为审计。 |

### 9.2 关键关联与不可变字段

从第二期开始，以下字段不得因页面展示简化而遗漏：

```text
资金来源（个人 / 企业）
资金归属个人账号 / 机构
操作主体与实际使用主体
机构成员关系与岗位快照
业务单号、调用单号、消费单号、充值订单号、发票申请单号
扣减前余额、扣减额、扣减后余额
成员额度前值、扣减额、后值（适用时）
智能体、计费规则/版本、调用时间
对账状态、发票资格状态、外部接口状态
```

建议将名称、岗位、智能体版本等会变化的信息保留“快照字段”，保证历史记录可解释。

## 10. 权限与页面实施蓝图

### 10.1 建议页面

| 端与页面 | 第二期 | 第三期 |
| --- | --- | --- |
| 企业主账号 / 用户端：企业彩豆 | 企业共享余额、充值、余额预警、企业消费明细、成员额度 | 预算、分析、对账摘要、财务工作台。 |
| 企业子账号 / 用户端：我的彩豆 | 个人余额、企业可用资格/额度、扣减说明、个人消费明细 | 额度申请、个人开票进度（按权限与实际规则）。 |
| 开发者端 | 与机构属性一致的共享彩豆、成员额度、收入/结算关联视图 | 经营分析与财务对账能力按开发者业务模型适配。 |
| 财务端 | 复用订单、充值、消费和发票资格数据，支持审核待办 | 发票审核、对账、差异处理、外部系统接口状态。 |
| 运营端 | 只读审计与异常处理范围按运营职责授权 | 规则治理、异常协同、跨机构风险监控（需额外确认数据边界）。 |

### 10.2 原型实施顺序

1. 先补齐企业主账号的“企业共享彩豆”和子账号“我的彩豆”两个入口；
2. 完成个人优先、企业兜底的调用前校验与扣减结果展示；
3. 完成企业消费明细、成员额度和余额预警的管理闭环；
4. 在既有发票页面补充“充值/消费 × 个人/企业”的来源筛选、资格状态与申请主体；
5. 最后建设财务工作台、对账差异、预算与审计页面，确保从汇总能下钻到原始单据。

> 静态原型中只能展示状态和交互路径；真实系统必须由服务端完成余额原子扣减、鉴权、幂等、账本写入与金额核验。

## 11. 风险与治理要求

| 风险 | 影响 | 方案要求 |
| --- | --- | --- |
| 企业与个人资金混淆 | 错误扣减、错误开票、客户争议 | 所有账本和消费拆分强制记录资金来源与归属。 |
| 并发调用超扣 | 余额为负或账实不一致 | 服务端原子扣减、账户版本号/锁、消费幂等键与失败补偿。 |
| 权限变更后仍可用企业资金 | 越权消费 | 每次企业扣减实时校验成员状态、岗位权限和额度策略。 |
| 调用失败仍扣费 | 客诉与财务差异 | 消费状态、调用结果、冲正/不扣费规则必须可关联、可审计。 |
| 发票重复占用 | 重复开票或金额错配 | 发票资格金额占用、状态机和单据关联强校验。 |
| 税务规则未经确认 | 方案与实际合规要求冲突 | 财税确认税率、品目、纳税义务时点、作废/红冲规则后再定稿。 |
| 外部对接结果不确定 | 银行/金蝶/税务对账失败 | 用接口状态、回传记录、差异单承接；不得以页面成功提示替代外部成功。 |

### 测试与演示约束

- 所有新增测试数据须使用 `QA-TEST-` 前缀或标注“仅供测试、非真实”；
- 不得使用真实身份证、营业执照、发票或收款账户；
- 外部系统仅验证平台待处理状态、接口状态或回传结果展示，不向真实支付、银行、金蝶或税务系统提交生产业务；
- 不操作归属不明或可能关联真实业务的智能体、结算单、提现单、发票或账户。

## 12. 验收标准

| 编号 | 验收标准 |
| --- | --- |
| AC01 | 企业充值成功后，彩豆只计入机构企业共享彩豆账户，不形成子账号名下的企业余额。 |
| AC02 | 子账号调用时优先扣个人彩豆；个人不足时，仅在具备企业彩豆使用权限、成员未停用、额度充足且企业余额充足的情况下扣企业共享彩豆。 |
| AC03 | 一次混合消费必须生成个人和企业两条来源拆分记录，拆分金额之和等于调用总消费。 |
| AC04 | 企业消费记录可追溯到实际调用子账号、机构成员关系、岗位快照、智能体、调用单、计费版本和扣减前后余额。 |
| AC05 | 成员额度至少支持不限额、单次上限、自然月周期上限；额度仅限制企业来源实际扣减额。 |
| AC06 | 企业共享余额和成员额度达到预警阈值时，主账号及被授权成员收到可识别、可处理的通知；达到上限或余额不足时不得执行对应企业扣减。 |
| AC07 | 个人充值、企业充值、个人消费、企业消费四类记录均具有独立资金归属、申请主体、可开金额、占用金额和发票状态。 |
| AC08 | 同一笔充值或消费金额不得被重复申请发票；混合消费的个人和企业部分不可混合申请。 |
| AC09 | 企业主账号或财务权限成员可按成员、智能体、时间、资金来源查询企业消费明细，并导出授权范围内数据。 |
| AC10 | 对账页面可关联充值订单、支付/银行状态、彩豆账本、调用消费、发票申请；差异具备状态与处理记录。 |
| AC11 | 关键财务和管控操作（权限、额度、预警、发票、对账）均记录操作人、时间、对象、前后值及关联单号。 |
| AC12 | 本期不提供企业回收未消费余额、企业充值退款、子账号离职/停用后的余额处置功能。 |

## 13. 待财税与业务确认项

以下事项不应由产品假设决定，需在研发实施前形成书面确认：

1. “充值发票”与“消费发票”是否均为正式业务口径，以及各自适用的交易/税务依据；
2. 发票抬头、税号、品目、税率、开票周期、纳税义务时点和作废/红冲规则；
3. 企业消费是否允许按项目、部门或多个成本中心拆分抬头或辅助核算；
4. 调用异常、计费失败、服务降级时的最终扣费和冲正规则；
5. 成员额度是否需要审批、谁可审批、临时额度的有效期；
6. 银行、金蝶、税务系统的实际接口边界、对账频率、失败重试和人工介入责任人；
7. 个人彩豆与企业共享彩豆在成员离职、机构停用、账号注销等后续场景的处置规则。

## 14. 里程碑建议

| 阶段 | 交付重点 | 完成标志 |
| --- | --- | --- |
| 方案确认 | 财税口径、权限、额度、异常扣费规则确认 | 数据字典、状态机、接口边界冻结。 |
| 第二期原型与研发 | 共享池、个人优先扣减、权限、额度、明细与预警 | 可完整演示企业充值—成员调用—来源拆分—企业追溯链路。 |
| 第三期原型与研发 | 发票资格、财务工作台、对账、分析、审计 | 可从财务汇总下钻至订单、账本、消费与申请单；差异可闭环。 |
| 联调与验收 | 压测、幂等、权限、数据一致性与财务验收 | 所有 AC 达成，外部系统仅在授权测试环境完成验证。 |

---

**最终定位**：第二期不是简单的“彩豆余额功能”，而是为第三期财务能力建立可追溯的资金来源、扣减与账本基础；第三期也不是单独新增页面，而是基于同一条资金—消费—发票—对账链路提供管理和审计能力。
