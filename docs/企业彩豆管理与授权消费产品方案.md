# 彩翼平台企业彩豆管理与授权消费产品方案

> **版本**：V1.6  
> **日期**：2026-08-25  
> **覆盖范围**：企业共享彩豆池、成员额度授权、来源拆分消费与开票口径  
> **前置方案**：[机构主子账号与岗位权限产品方案](../机构主子账号与岗位权限产品方案.html)

---

## 1. 背景与结论

机构客户需要让员工使用智能体，企业充值的彩豆既要多人协同使用，又要明确资产归属、实际使用人和可开票金额。若把企业彩豆逐笔划转给子账号，会带来余额回收、离职处置、个人与企业余额混合、开票归属不清等问题，并放大后续对账复杂度。

### 1.1 产品结论

采用 **企业共享彩豆池 + 子账号授权消费**，不建设“主账号向子账号分配企业彩豆余额”的能力。

```text
机构主账号充值
  → 企业共享彩豆池入账（企业资产）
  → 子账号按授权额度使用
  → 调用优先扣个人彩豆
  → 个人不足时，扣企业共享彩豆
  → 每次消费分别记录个人 / 企业实际扣减额
```

### 1.2 方案价值

| 目标 | 方案如何实现 |
| --- | --- |
| 企业资产不转移 | 企业彩豆始终留在机构共享池，不形成子账号名下的企业余额。 |
| 员工使用可控 | 需由主账号配置使用额度（初始为 0），并受周期额度与余额预警约束。 |
| 消费责任可追溯 | 每笔企业消费记录实际调用人、岗位、智能体、调用单与扣减额。 |
| 个人与企业财务清晰 | 个人与企业的充值、消费独立入账；充值可开票金额按主体独立累计。 |

## 2. 目标、范围与边界

### 2.1 本期目标与纳入能力

**目标**：让企业主账号充值后的共享彩豆，可由获得额度授权的子账号安全、可追溯地使用。

| 纳入能力 | 说明 |
| --- | --- |
| 企业共享彩豆池 | 企业充值入企业共享池，余额归机构，不转移给成员。 |
| 个人彩豆余额 | 子账号可自行充值，余额归平台个人账号。 |
| 统一调用扣减 | 优先个人后企业的来源拆分扣减。 |
| 企业彩豆使用授权 | 由具备企业彩豆管理权限的成员配置成员使用额度；初始为 0，不设独立的使用权限项。 |
| 成员消费额度 | 最小实现支持「不限额、周期上限」；周期按自然月。 |
| 企业余额预警 | 企业共享池低于阈值时通知主账号及具备企业彩豆管理权限的成员。 |
| 个人与企业消费明细 | 以资金来源拆分查看、导出和追溯。 |
| 发票资格基础 | 充值可开金额按个人 / 企业分别累计；消费可开金额按消费订单整笔累计。 |

### 2.2 明确不在本期范围

以下能力不在本期范围内，后续另行评估：

1. 企业回收已授权但未消费的企业彩豆；
2. 企业充值退款；
3. 子账号离职或停用后的余额处置。

> 企业共享彩豆不划至成员名下，因此不存在“回收成员名下企业余额”的问题。个人彩豆的归属、退款与离职后账号处理，另行专项定义。

---

## 3. 核心账务原则

1. **资金来源不可丢失**：任何余额、消费与开票记录都必须可追溯到个人或企业来源。  
2. **资产归属不可混淆**：个人彩豆归个人；企业共享彩豆归机构；可用资格不等于资产所有权。

## 4. 账户、余额与扣减模型

### 4.1 账户定义

| 账户 | 所有者 | 资金来源 | 使用者 | 余额展示 |
| --- | --- | --- | --- | --- |
| 个人彩豆账户 | 平台个人账号 | 子账号本人充值、后续平台活动赠送（如有） | 账号本人 | 子账号个人余额 |
| 企业共享彩豆账户 | 机构 | 机构主账号或拥有企业彩豆管理权限的成员代表机构充值 | 已配置额度且未超额度的机构成员 | 企业共享余额；成员侧仅展示本人可用额度 |

### 4.2 子账号可用金额展示

子账号调用页面应分开呈现，避免把企业资产误理解为个人余额：

```text
个人彩豆：120
企业共享彩豆：可使用（本月剩余额度 80）
本次预计消耗：10
扣减顺序：优先个人彩豆，个人不足时使用企业共享彩豆
```

未配置额度的成员，企业共享彩豆额度展示为 0。

### 4.3 标准扣减规则

设一次调用应消费 `C` 彩豆，成员个人余额为 `P`，企业共享池余额为 `E`，成员当前可使用的企业额度为 `L`。

```text
个人扣减 = min(C, P)
企业待扣 = C - 个人扣减
企业实际扣减 = min(企业待扣, E, L)
```

若 `个人扣减 + 企业实际扣减 = C`，调用可执行。

### 4.4 混合消费示例

| 项目 | 数值 |
| --- | ---: |
| 本次调用总消费 | 10 彩豆 |
| 调用前个人彩豆 | 6 彩豆 |
| 调用前企业共享彩豆 | 200 彩豆 |
| 成员当期企业可用额度 | 40 彩豆 |
| 个人实际扣减 | 6 彩豆 |
| 企业实际扣减 | 4 彩豆 |

生成一笔调用消费单与两条来源拆分明细：个人 6、企业 4。开票由实际消费人按 10 彩豆整笔申请，来源拆分只用于账本记录与成本追溯。

## 5. 功能设计

### 5.1 企业共享彩豆池

#### 功能点

- 企业充值订单支付成功后，彩豆计入机构共享彩豆账户；
- 企业共享余额、冻结额（如后续引入）、可用额、累计充值、累计企业消费分开展示；
- 主账号及拥有企业彩豆管理权限的成员可查看企业充值和企业消费明细；
- 充值订单、彩豆入账记录和后续发票申请可相互关联。

#### 余额变动口径

| 场景 | 企业共享池变化 | 记录要求 |
| --- | --- | --- |
| 企业充值支付成功 | 增加 | 关联充值订单、支付结果、入账时间与操作主体。 |
| 子账号调用使用企业彩豆 | 减少 | 关联调用消费单、实际使用人、智能体和企业扣减额。 |
| 调用失败/撤销且确认不计费 | 冲回或不扣减 | 保留原消费单与冲正/失败原因。 |

> 本期不提供企业充值退款。账务异常仅预留内部标记与人工处理入口字段，不自行定义退款流程。

### 5.2 企业彩豆岗位权限

#### 企业彩豆使用不设独立权限，由额度授权控制

企业彩豆的使用资格**不设岗位权限项**：机构全体成员默认具备使用资格，但初始使用额度为 0，未配置额度前不可使用企业彩豆。

| 决策 | 理由 |
| --- | --- |
| 不设「使用企业彩豆」权限项 | 「有权限但额度为 0」与「有额度但权限被撤」含义重复且可能矛盾；额度本身即授权凭证。 |
| 默认额度为 0 | 默认全员不可用，主账号只需为需要的成员配置额度，无需逐个禁用。 |
| 授权入口唯一 | 「企业彩豆 · 成员企业彩豆额度」是配置使用额度的唯一入口，由 `enterprise_bean.manage` 控制。 |

界面上**不区分「无使用资格」与「额度为 0」两种状态**：未配置额度的成员，其「我的彩豆」界面结构与已授权成员一致，本月企业额度展示为 0 并提示尚未配置额度。

#### 与企业彩豆相关的两项权限

| 权限编码（建议） | 权限名称 | 所属菜单 | 类型 | 作用 |
| --- | --- | --- | --- | --- |
| `enterprise_bean.manage` | 企业彩豆管理 | 企业彩豆（菜单权限与管理操作二合一） | 菜单 | 代表机构创建企业充值订单；查看企业共享余额与充值、消费明细；配置成员使用额度与余额预警。 |
| `account-company` | 维护机构对公账户 | 付款账户 | 按钮 | 对公账户的新增、编辑、删除、设为主账户、设为默认付款账户。 |

- 企业充值发票由主账号或具备 `enterprise_bean.manage` 的成员代表机构申请；消费发票统一由实际消费人申请，不单设发票申请权限；
- 两项权限互不覆盖：`enterprise_bean.manage` 不含对公账户维护，`account-company` 不含企业充值；分属两个菜单，可授予不同成员；
- 「企业彩豆」菜单可见性由 `enterprise_bean.manage` 控制；不具备该权限的成员，企业相关可见范围仅限本人使用额度与本人产生的企业来源消费、开票记录。

### 5.3 成员额度控制

#### 最小实现

每个机构成员可以配置一条企业彩豆使用额度策略：

| 模式 | 规则 |
| --- | --- |
| 不限额 | 企业余额充足时即可使用。 |
| 周期上限 | 当前自然月内累计最多使用指定数额的企业彩豆。 |

额度仅限制**企业来源实际扣减额**，不限制成员使用个人彩豆。

### 5.4 企业余额预警

| 触发条件 | 通知对象 | 动作 |
| --- | --- | --- |
| 企业共享余额低于固定阈值 | 主账号、企业彩豆管理权限成员 | 站内通知 + 待办提示 |
| 成员周期额度达到 80% / 100% | 成员本人、主账号或企业彩豆管理人 | 站内提醒；达到上限后阻止企业扣减 |

### 5.5 企业消费明细

企业消费明细是财务衔接的核心页面，至少应支持按时间、成员、智能体和资金来源筛选、分页与导出。

必备字段：

```text
消费单号
调用时间
实际调用子账号 / 平台个人账号
所属机构 / 成员岗位快照
智能体名称、智能体 ID、计费版本
调用/业务单号
本次总消费
个人彩豆扣减额
企业共享彩豆扣减额
企业扣减前余额 / 后余额
成员周期额度前值 / 后值（适用时）
消费状态、冲正关联单
企业消费开票状态
```

## 6. 充值、消费与开票规则

### 6.1 资金口径与发票申请

资金在账本层始终按个人 / 企业来源拆分记录；发票申请层按以下口径执行：

| 业务口径 | 资产归属 | 申请主体 | 可开金额来源 | 备注 |
| --- | --- | --- | --- | --- |
| 个人充值发票 | 个人 | 子账号本人 | 个人充值订单 | 一笔充值订单只能进入一次充值发票申请。 |
| 企业充值发票 | 机构 | 主账号或具备 `enterprise_bean.manage` 的成员（代表机构） | 企业充值订单 | 申请人代表机构操作，不改变企业资产归属。 |
| 消费发票 | 账本层按来源拆分记账 | 实际消费人本人 | 消费订单整笔金额 | 不论个人、企业或混合来源，均由实际消费人整笔申请一次；资金来源仅用于账本记录与追溯，不作为拆分依据。 |

### 6.2 付款账户与资金来源约束

#### 6.2.1 账户归属与维护权限

| 账户类型 | 资产归属 | 可维护主体 | 覆盖操作 |
| --- | --- | --- | --- |
| 个人支付方式 | 个人 | 平台个人账号本人 | 微信、支付宝、个人银行卡的绑定、解绑与设为默认。 |
| 机构对公账户 | 机构 | 机构主账号，或具备 `account-company`（维护机构对公账户）权限的成员 | 新增、编辑、删除、设为主账户、设为默认付款账户。 |

- 不具备 `account-company` 的成员，对公账户**仅可在企业充值时选择使用**（发起企业充值另需 `enterprise_bean.manage`），不可新增、编辑、删除或设为主账户、默认付款账户；
- 个人账号不可查看其所属机构以外的任何对公账户；
- 对公账户开户名称必须与机构注册主体一致，不得绑定为个人姓名；
- 主/子账户与默认付款账户是两个独立维度：前者描述银行侧层级，后者决定企业充值默认选中的账户，两者不必相同；每个机构同时只允许一个默认对公付款账户；
- 对公账户变更属资金流向变更，须记录操作人、时间与前后值，纳入操作审计。

#### 6.2.2 资金来源一致规则

付款账户类型**不由用户自由选择，由充值目标账户决定**：

| 充值目标 | 允许的付款方式 | 权限要求 |
| --- | --- | --- |
| 个人彩豆账户 | 个人支付方式（微信 / 支付宝 / 个人银行卡） | 无 |
| 企业共享彩豆池 | 机构对公账户 | `enterprise_bean.manage` |

以下两种交叉场景均不允许：

1. **个人充值用机构对公账户**：企业资金变成个人资产，且绕过 `enterprise_bean.manage` 动用机构资金，付款主体与发票主体也不一致。
2. **企业充值用个人支付方式**：形成“个人付款、机构收资产、机构开票”的三方不一致，订单无法与银行流水按主体匹配，也不满足企业进项合规。

成员垫付企业费用的诉求不通过充值路径解决，另行定义。

### 6.3 账户充值页展示与术语约定

1. **充值记录按当前账户上下文展示**：“个人充值”页签只看个人记录，“企业充值”页签只看企业记录；上下文已明确时，列表不重复展示“个人/企业”类型字段。  
2. **跨账户场景保留归属标识**：充值详情、发票详情、财务对账、资金流水与导出报表须展示资金归属、充值主体或账户类型，以支撑开票与审计追溯。  
3. **企业充值后的使用边界**：彩豆计入机构共享池，仅已配置额度且未超额度的成员可使用；额度不形成个人余额，也不改变企业资产归属。

### 6.4 消费发票申请约束

1. 一笔消费订单只能整笔申请一次对应的**消费发票**，由实际消费人发起；
2. 混合消费在账本层按个人与企业来源拆分记录；发票申请不按来源拆分，不得重复申请或重复占用；
3. 充值与消费两个税务口径能否并存，以及税率、品目、纳税义务时点与红冲规则，须由财税确认；平台提供可核验、可追溯的数据基础与流程承载。

## 7. 核心流程

### 7.1 企业充值入账

```text
主账号 / 企业彩豆管理权限成员创建充值订单
  → 支付渠道返回支付结果
  → 订单状态确认成功
  → 企业共享彩豆账户原子入账
  → 生成企业充值账本
  → 产生企业充值发票可申请资格
  → 通知相关成员并进入对账待核对范围
```

### 7.2 子账号智能体调用与来源扣减

```text
子账号发起调用
  → 校验机构成员状态、智能体权限与计费参数
  → 计算本次应消费金额
  → 优先校验并扣减个人彩豆
  → 如有剩余：校验成员额度与企业余额
  → 原子扣减企业共享彩豆
  → 创建调用消费单与个人/企业来源拆分账本
  → 更新消费可开金额、成员额度与预警状态
  → 返回调用结果及扣减明细
```

### 7.3 消费发票申请

```text
实际消费成员筛选本人可开票消费订单
  → 发起消费发票申请（整笔，不按资金来源拆分）
  → 占用对应消费订单开票资格
  → 财务审核
  → 开具 / 驳回 / 进入外部接口处理状态
  → 更新申请、资格、账本关联状态
  → 全程保留实际使用子账号、消费明细与资金来源拆分的追溯链路
```

```text

成员额度前值、扣减额、后值（适用时）
智能体、计费规则/版本、调用时间
对账状态、发票资格状态、外部接口状态
```

| 端与页面 | 本期内容 |
| --- | --- |
| 企业主账号 / 用户端：企业彩豆 | 企业共享余额、充值、余额预警、企业消费明细、成员额度 |
| 企业子账号 / 用户端：我的彩豆 | 个人余额、本月企业额度、扣减说明、个人消费明细；未配置额度的成员界面结构一致，额度展示为 0 |
| 开发者端 | 与机构属性一致的共享彩豆、成员额度、收入/结算关联视图 |
| 财务端 | 复用订单、充值、消费和发票资格数据，支持审核待办 |
| 运营端 | 只读审计与异常处理范围按运营职责授权 |

两个入口的内容边界必须严格区分，避免成员视图与机构管理视图混装：

- 「我的彩豆」只展示本人的个人彩豆资产、企业使用额度、扣减规则与消费明细，**不展示企业共享池总额、成员额度配置入口或其它成员用量**；变动明细中的企业扣减只显示本次扣减额，不显示共享池前后余额（该余额按第 8 章保留在数据层）；
- 企业消费明细以「企业彩豆」为正式承载页；消费记录页的「全机构企业消费」是面向 `enterprise_bean.manage` 成员的快捷视图，两者口径一致；
- 「企业彩豆」承载机构资产视图（共享池余额、企业充值、余额预警、企业消费明细、成员额度配置），仅对主账号与具备 `enterprise_bean.manage` 的成员可见；

### 9.2 权限—界面控制矩阵（用户端）

界面显隐与可操作性一律以**权限编码**判断，岗位是权限的集合；不得以角色名或岗位名硬编码界面逻辑。

| 菜单 | 菜单权限编码 | 其下功能权限 | 控制的页面内元素 |
| --- | --- | --- | --- |
| 概览 | `overview-view` | — | 整页 |
| 智能体市场 | `market-view` | `market-edit` 配置智能体使用 | 整页；智能体使用配置入口 |
| 账户充值 | `recharge-view` | — | 整页；企业充值页签另需 `enterprise_bean.manage` |
| 付款账户 | `payment-view` | `account-company` 维护机构对公账户 | 整页（个人付款方式）；对公账户区块的新增、编辑、删除、设为主账户、设为默认付款账户 |
| 我的彩豆 | `balance-view` | — | 整页（个人彩豆资产、本月企业额度、「个人优先、企业兜底」扣减说明与变动明细）。企业彩豆能否实际扣减取决于成员使用额度，不由权限控制 |
| 企业彩豆 | `enterprise_bean.manage` | —（菜单权限与管理操作二合一） | 企业共享池余额、企业充值、企业充值 / 消费明细、成员使用额度配置、余额预警；消费记录页的全机构企业消费视图 |
| 消费记录 | `consumption-view` | `account-export` 导出消费记录 | 整页，数据范围限本人；导出按钮 |
| 发票管理 | `invoice-view` | `invoice-edit` 维护开票信息 | 整页；消费发票申请入口对实际消费人开放；开票信息（抬头、税号）维护 |
| 账号管理 | `org-account` | `org-edit` 维护成员账号 | 成员列表与详情；新增成员、调整岗位、停用/恢复 |
| 岗位管理 | `org-role` | — | 岗位列表、详情与权限配置 |

补充说明：

1. 少数能力跨菜单生效，需同时校验两个权限：账户充值页的「企业充值」页签需 `recharge-view` + `enterprise_bean.manage`；消费记录页的「全机构企业消费」视图需 `consumption-view` + `enterprise_bean.manage`；
2. 无对应菜单权限的成员，直接访问页面 URL 时服务端必须拒绝；原型仅演示菜单与元素的显隐，不代表前端隐藏即完成权限控制；
3. **企业彩豆的使用资格不由权限控制**：全体成员默认具备资格、初始额度为 0，实际能否扣减企业彩豆取决于成员使用额度（见 5.2）。

### 9.3 原型实施顺序

1. 先补齐企业主账号的“企业共享彩豆”和子账号“我的彩豆”两个入口；
2. 完成个人优先、企业兜底的调用前校验与扣减结果展示；
3. 完成企业消费明细、成员额度和余额预警的管理闭环；
4. 在既有发票页面补充“充值/消费 × 个人/企业”的来源筛选、资格状态与申请主体；
5. 最后建设财务工作台、对账差异、预算与审计页面，确保从汇总能下钻到原始单据。

> 静态原型中只能展示状态和交互路径；真实系统必须由服务端完成余额原子扣减、鉴权、幂等、账本写入与金额核验。

## 10. 风险与应对

| 风险 | 影响 | 方案要求 |
| --- | --- | --- |
| 企业与个人资金混淆 | 错误扣减、错误开票、客户争议 | 所有账本和消费拆分强制记录资金来源与归属。 |
| 额度调整后仍可用企业资金 | 越额消费 | 每次企业扣减实时校验成员状态与额度策略，额度归零后立即停止企业扣减。 |
| 税务规则未经确认 | 方案与实际合规要求冲突 | 财税确认税率、品目、纳税义务时点、作废/红冲规则后再定稿。 |

## 11. 验收标准

| 编号 | 验收标准 |
| --- | --- |
| AC01 | 企业充值成功后，彩豆只计入机构企业共享彩豆账户，不形成子账号名下的企业余额。 |
| AC02 | 子账号调用时优先扣个人彩豆；个人不足时，仅在成员未停用、已配置使用额度且额度与企业余额均充足的情况下扣企业共享彩豆；额度为 0 的成员不得发生企业扣减。 |
| AC03 | 一次混合消费必须生成个人和企业两条来源拆分记录，拆分金额之和等于调用总消费。 |
| AC04 | 企业消费记录可追溯到实际调用子账号、机构成员关系、岗位与额度快照、智能体、调用单、计费版本和扣减前后余额。 |
| AC05 | 成员额度至少支持不限额、自然月周期上限；额度仅限制企业来源实际扣减额。 |
| AC06 | 企业共享余额和成员额度达到预警阈值时，主账号及被授权成员收到可识别、可处理的通知；达到上限或余额不足时不得执行对应企业扣减。 |
| AC07 | 充值发票按个人 / 企业独立记录资金归属、申请主体、可开金额、占用金额和发票状态；消费发票按消费订单整笔记录申请状态，账本层保留个人 / 企业来源拆分。 |
| AC08 | 同一笔充值订单或消费订单不得重复申请发票；混合消费不拆分申请，由实际消费人整笔申请一次。 |
| AC09 | 企业主账号或企业彩豆管理权限成员可按成员、智能体、时间、资金来源查询企业消费明细，并导出授权范围内数据。 |
| AC10 | 本期不提供企业回收未消费余额、企业充值退款、子账号离职/停用后的余额处置功能。 |

## 12. 待财税与业务确认项

以下事项不应由产品假设决定，需在研发实施前形成书面确认：

1. “充值发票”与“消费发票”是否均为正式业务口径，以及各自适用的交易/税务依据；
2. 发票抬头、税号、品目、税率、开票周期、纳税义务时点和作废/红冲规则；
3. 企业消费是否允许按项目、部门或多个成本中心拆分抬头或辅助核算；
4. 调用异常、计费失败、服务降级时的最终扣费和冲正规则；
5. 成员额度是否需要审批、谁可审批、临时额度的有效期；
6. 银行、金蝶、税务系统的实际接口边界、对账频率、失败重试和人工介入责任人；
7. 个人彩豆与企业共享彩豆在成员离职、机构停用、账号注销等后续场景的处置规则；
8. 消费发票整笔申请（不按资金来源拆分）的税务合规性，以及企业来源消费计入实际消费人所选抬头时的进项处理规则。
