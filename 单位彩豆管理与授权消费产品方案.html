单位彩豆管理与授权消费

单位彩豆全员共有，成员能做什么由岗位菜单权限决定。以单一账户、单一扣减来源和清晰的记录可见范围，换取更低的管理成本与同等的风险可控性。

01

方案结论：全员共有，权限治理

不再采用「企业共享池 + 逐成员配置使用额度」的模型。企业身份下只有一个彩豆账户，属于机构；成员能不能充值、能不能消费、能看到多大范围的记录，一律由岗位菜单权限决定。

采用：单位彩豆共有 + 菜单权限治理

有充值权限即可充值（付款可选个人支付或机构对公账户），有智能体市场权限即可消费，无需为每个成员配置额度。

不采用：成员额度制（V1.6）

额度制要求主账号逐人配置并持续维护，管理成本大于风险收益；且「资格 / 额度 / 权限」三层控制含义重叠，易产生互相矛盾的状态。

02

范围与边界

本期明确不做

  • 成员额度、部门预算、单笔消费上限等额度类控制；
  • 企业充值退款与已充值彩豆回收；
  • 成员离职或停用后的账户处置流程；
  • 消费的事前审批流（先消费后追溯）。
边界说明：取消额度制后，「回收成员额度」与「额度审批」两类需求随之消失。若后续机构反馈需要事前控制，优先评估部门预算而非恢复逐人额度。

个人用户端不受影响

「共有」仅在企业身份工作台内生效。个人用户仍是独立的个人彩豆账户，自行充值、消费、开票。同一手机号同时拥有个人身份与机构成员身份时，两个工作台的余额、记录与发票完全隔离。

03

账户、余额与扣减模型

账户资金归属充值主体可使用人余额展示
单位彩豆账户机构有充值菜单权限的成员有智能体市场权限的成员彩豆管理页展示机构余额
个人彩豆账户平台个人账号个人身份下本人账号本人仅个人工作台展示

企业身份工作台内不再出现「个人彩豆」概念，也不存在成员名下的企业余额。

扣减规则

调用可执行条件 = 单位彩豆余额 E ≥ 本次应消费 C
扣减额 = C
扣减后余额 = E − C

无来源拆分、无额度校验、无优先级顺序。余额不足时调用被拒绝并提示充值。调用失败不产生扣费：保留消费单，消费金额为 0、余额不变、开票状态为不可开票（该口径待研发与财税确认）。

04

功能设计

最小功能集

彩豆管理

余额、本月充值/消费/成功调用、余额预警与全部变动明细（含操作人）。

账户充值

档位与自定义金额；付款方式同页并列个人支付与机构对公账户，入账结果一致。

消费资格

不设独立权限与额度，有智能体市场权限即可消费单位彩豆。

记录可见范围

有消费记录菜单权限的成员可查看全公司消费记录，并可按成员筛选。

发票能力

有发票菜单权限即可对全公司充值与消费订单申请开票。

余额预警

平台统一默认 500 彩豆，企业侧只读，触发后通知主账号与彩豆管理成员。

统计口径：「本月成功调用」只统计成功调用；失败调用出现在消费记录中但不计入该指标，彩豆管理、消费记录、概览三处口径一致。

消费详情字段

概览八项：消费单号、消费时间、智能体、消费人、调用状态、计费方式、调用渠道、开票状态。扣减明细四项：消费彩豆、对应金额、扣前余额、扣后余额。其中计费方式与调用渠道对齐现网运营端既有字段；Token 用量明细（输入/输出 token 数、单价）现网未提供，若后端已落库建议补充，是解释扣费金额最直接的字段。

05

充值、消费与开票：申请口径

业务口径资产归属申请主体可开金额
充值发票机构具备发票管理权限的成员全公司充值订单，一笔仅可申请一次
消费发票机构具备发票管理权限的成员全公司消费订单，按整笔申请；失败订单不可开票
新增维护权限：account-company（维护机构对公账户）归属「付款账户」菜单；具备该菜单权限并被授予该按钮权限的成员，可新增、编辑、删除及设置机构对公账户。该权限与充值权限解耦：可以充值但不能维护对公账户，也可以维护对公账户但不能充值；不具备维护权限的成员，对公账户仅可在充值时选用。
06

关键验收标准

编号验收结果
AC01充值成功后彩豆仅计入机构账户，不形成成员名下余额；两种付款方式入账结果一致。
AC02具备 market-view 即可调用并扣减，无需额外资格或额度；余额不足时调用被拒绝。
AC03每笔消费生成唯一消费单，扣前余额 − 消费额 = 扣后余额，并记录消费人、智能体、计费方式、渠道与调用状态。
AC04失败调用消费金额为 0、余额不变、不可开票，且不计入「本月成功调用」。
AC05具备 recharge-view 的成员可查看全公司充值记录，记录保留充值人与付款方式。
AC06具备 consumption-view 的成员可查看全公司消费记录并按成员筛选；无此菜单权限的成员无法获取消费数据。
AC07具备发票权限的成员可对全公司充值与消费订单开票；同一订单不得重复申请。
AC08余额低于平台默认阈值时通知主账号与彩豆管理成员；阈值企业侧只读。
AC09具备 payment-view 与 account-company（维护机构对公账户）的成员可新增、编辑、删除及设置机构对公账户；不具备该按钮权限的成员仅可在充值时选用。
AC10「本月成功调用」在彩豆管理、消费记录与概览三处口径一致。
AC11个人身份工作台的余额、记录与发票与任何机构账户完全隔离。
AC12本期不提供成员额度、部门预算、充值退款、彩豆回收与消费审批流。

本方案核心

单位彩豆全员共有，不划转单账户单来源，直接扣减控制点从额度转为菜单权限开票权归财务岗位，范围全公司

适用对象：机构主账号、机构成员、财务成员、运营/财务协同人员。
