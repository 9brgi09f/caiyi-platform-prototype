2 核心计算规则（含精度与用例）

2.1 彩豆与本金分摊系数

（1）兑换比例：1 元 = 100 彩豆（平台可配置，修改留痕、次月 1 日生效）。本期按 1:1 充值、暂不开放充值赠送；阶梯赠送（如满 30 送 5%、满 100 送 10%）为预留能力，配置界面保留、本期不生效。

（2）本金分摊系数 = 充值实付本金 ÷（购买彩豆 + 赠送彩豆），单位：元/彩豆。计算保留 6 位小数，展示保留 2 位。本期赠送 = 0，即系数 = 本金 ÷ 购买彩豆 = 0.01。

（3）消费现金口径金额 = 消费彩豆数 × 本金分摊系数，按分位（0.01 元）四舍五入；赠送彩豆对应额度不计入收入与分成基数。

用例（本期 1:1、无赠送）：充值 ¥30 → 3,000 彩豆，系数 = 30 ÷ 3,000 = 0.01；消费 1,000 彩豆现金口径 = ¥10.00。（若后续开放赠送：¥30 → 3,000 + 赠 150，系数 30 ÷ 3,150 = 0.009524，消费 1,000 彩豆 ≈ ¥9.52）

2.2 实时扣费

智能体支持 按 token 与 按次 两种计费方式，由开发者发布/编辑时二选一。（0723 财务确认：本期暂不支持按次计费，仅按 token 计费；按次机制描述保留备后续启用）按 token 计费（换算率由开发者定价，见下段）：单次扣费 = 本次实际消耗 token × 该智能体换算率，折算成彩豆扣除。流水记录：调用时间、调用 IP、智能体、消耗 token 数、换算率、彩豆数、现金金额、扣前/扣后余额。余额不足直接拦截调用；单次消耗超过智能体申报的"单次 token 上限"时截断提示；低余额提醒阈值 10 元。

换算率与市场展示：token→彩豆 换算率（计价规则）由开发者按智能体自主设定，随上架/变更审核生效，本期不区分大模型；平台仅配置算力成本单价（示例：每 1,000 token = 0.1 彩豆）作为定价下限，开发者换算率不得低于该值。开发者申报"单次预估 token 区间"，按其换算率折算成彩豆区间在市场展示（如 10~150 彩豆/次）；实际以本次真实消耗结算，输入较多时可能高于上限（市场区间为参考、非承诺价）。本期仅支持收费（自主定价），免费 / 会员功能暂不实现（相关配置已隐藏）。

按次计费（本期暂不支持，机制描述保留备后续启用）：除按 token 外，开发者发布/编辑时可选按次计费——用户每次调用固定扣除开发者设定的彩豆数（如 30 彩豆/次），与本次实际 token 消耗无关；市场按固定单价（N 彩豆/次）展示。按次计费的算力成本仍按实际消耗 token 计（每 1,000 token = 0.1 彩豆）并从开发者收入中扣除，开发者需申报"单次预估 token"用于估算算力成本，且每次价格 × 80% 不得低于预估算力成本（否则每次调用亏损、无法提交）。

2.3 开发者分佣

平台统一分佣比例 开发者 80% / 平台 20%（全平台唯一、随智能体上架自动执行，调整次月 1 日生效保证月度结算单比例唯一）。分佣金额 = 分佣基数 × 分佣比例 − 算力成本（分佣基数 = 用户消耗彩豆；按次计费时分佣基数 = 每次价格 × 有效调用次数（按次计费本期暂不支持，仅按 token 计费；该口径保留备后续启用）。先按 80/20 分成、再扣全额算力成本），即开发者最终收入 =用户消耗彩豆 × 80% − 算力成本彩豆；算力成本单价见 2.2。分佣实时入账，按月 1 日生成结算单；运营确认 + 开发者确认后计入可提现金额；开发者超 5 个工作日未确认，逾期并入下月结算。

2.4 渠道分成

（1）分成基数 = 推荐客户实际产生收入（不含税）− 退款（本期不实现，预留回冲设计）。现金口径 = 消费彩豆 × 本金分摊系数；不含税 = 现金口径 ÷ 1.06。

（2）客户推荐模式按"年度累计基数"分段计提，只对落入档位的部分按该档比例计算（上限比例，实批可下调）：

年度累计分成基数（扣除增值税后）新客户上限存续客户上限
3 万元（含）以下部分20%10%
超 3 万至 10 万（含）部分25%15%
超 10 万元的部分30%20%

（3）年度累计自首次推荐关系确认之日起算，每满一个自然年度清零；月度结算单金额 = 当月新增基数落入各档位部分 × 对应比例之和。

（4）联合共创 / 生态共建：不走阶梯，按"协议比例登记表"逐户登记的比例 × 分成基数计算；生态共建上限 80%（基数再减已支付的其它渠道分成），超限须主任办公会特批并登记纪要编号。

跨档验收用例（原型演示数据）：智采科技 6 月累计从 ¥27,200 → ¥46,200，新增 ¥19,000 = 2,800×20% + 16,200×25% = ¥4,610.00。

2.5 提现发票扣减

（0723 财务确认新口径）开发者/渠道商发起提现时即选择开票税率（6% / 3% / 1%，必须为增值税专用发票，普通发票不允许；抬头：广州市政府采购中心）。选 1%、3% 专票分别按 结算金额 × 5.29% / 3.11% 扣减分成款，选 6% 专票不扣减；提现金额 = 结算金额 − 扣减金额，发票金额必须与提现金额完全一致。开票税率在发起提现时选择，上传发票环节不再选择税率、不再计算扣减、不可调整；提现不收取手续费。用例：结算 ¥1,680 选 3% 专票 → 扣减 = 1,680 × 3.11% = ¥52.25，提现金额 = 发票金额 = ¥1,627.75。

2.6 留存倒挂校验

规则配置时校验：开发者分佣比例 + 渠道阶梯最高上限 > 100% 触发黄色预警（示例：开发者 80% + 渠道 30% = 110%，超 100% 触发预警），预警不阻断，提示按《办法》第十四条在上限内审慎确定实批比例。渠道分成由平台留存承担，不冲减开发者分佣与结算金额。

4.2 银企直联（浦发）

付款由金蝶发起银企直联转账，结果异步回写：成功 → 提现单已付款 + 发票核销 + 生成电子回单；失败 → 状态挂起进对账差异。幂等键：业务单号（提现单号）唯一，重复推送以单号去重。

4.3 数电发票

（1）销项：用户发票经运营审核后调数电开票，回写 20 位发票号码。（2）进项查验：提现上传的发票校验四要素——发票号码（20 位）、价税合计 = 提现金额（发票金额与提现金额完全一致）、抬头 = 广州市政府采购中心、票种/税率 = 增值税专用发票且税率与申请提现时所选一致（6%/3%/1%，普票不允许；扣减已在申请时按 2.5 计算，上传环节不再计算/调整）。

4.4 兜底机制

对账报表 T+1 三维核对（平台 ↔ 银行流水 / 支付渠道 / 金蝶），差异逐笔登记处理留痕；月度对账报表汇总。接口失败重试 3 次后转人工差异处理，不自动冲正。

8 非功能要求
