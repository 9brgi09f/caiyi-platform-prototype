1 文档定位

本文档说明彩翼平台的公开注册、企业/机构审核、身份切换与机构成员管理规则，并与当前静态原型保持一致。

原型、需求说明与本文档存在冲突时，以最新确认的账号模型为准。当前验证码、OCR、审核、通知、账户初始化与密码重置均为静态交互模拟，不代表已接入正式服务。

2 用户端身份模型

2.1 统一身份结构

平台个人账号（手机号唯一、长期保留）
└─ 机构成员关系（可新增、停用、移除）
　　├─ 机构主账号身份
　　└─ 机构子账号身份（管理员 / 操作员 / 只读）

个人账号是平台登录主体。加入机构只新增成员关系，不删除、不转移个人账号；同一人可同时拥有个人身份及多个机构身份。登录后的最小切换单元为「机构 + 成员角色」，而不是单独的机构类型。

2.2 角色端划分

端包含类型说明
使用者端采购单位、供应商、代理机构、个人用户、采购监管个人用户是平台个人账号的注册场景，实名后免审开通试用；采购监管由运营后台建档。
开发者端开发者（企业机构）审核通过后，当前个人账号取得该开发者机构的主账号成员关系。
渠道端渠道商本期不纳入当前公开注册主链路。

4 账号体系设计

4.1 平台个人账号与手机号

手机号全平台唯一，对应一个平台个人账号并作为登录账号。已注册手机号再次申请机构身份时，应由该账号登录后发起申请，或在流程中识别并关联已有账号；不得通过跨类型重复注册创建另一份登录账号。

4.1.1 运营创建个人账号

运营端“机构管理 → 账号管理 → 个人账号”支持运营协助开户和线下资料建档。该操作创建的是平台个人账号，不创建机构账号或机构成员关系；账号创建后可由本人登录使用，也可在后续审核通过后关联机构身份。

规则项规则说明
适用场景线下开户资料补录、客服协助开户、运营纠错后的合规建档；不得作为批量导入、营销拉新或绕过公开注册流程的通道。
必填与校验姓名、身份证号、手机号、初始密码必填；手机号和身份证号均需全平台唯一校验。正式系统应接入实名核验与短信/人工核验，原型仅演示表单交互。
账号状态与登录创建成功后账号激活；初始密码需安全哈希保存，并在首次登录时引导修改。不得在页面、日志或通知中记录明文密码。
免费体验边界运营后台创建的个人账号不自动发放“新注册用户”免费体验权益，避免与面向公开新注册用户的运营规则混淆；如后续需要发放，应通过独立的权益补发流程并留痕。
审计要求记录创建人、创建时间、创建来源、备注、实名/手机号校验结果和后续修改记录；创建权限仅授予已授权运营角色。

4.2 企业主体与机构身份

统一社会信用代码为企业主体唯一键。相同信用代码申请新的机构类型时，系统带出已登记的组织名称，并对本次机构身份单独审核。审核通过后，向当前个人账号新增对应机构的主账号成员关系；各机构的资源、余额、数据和权限保持隔离。

4.3 主账号与成员角色

机构主账号是成员关系中的最高权限身份，而非新的平台账号。主账号可被同一人在不同机构或类型下持有，不能跨机构管理资源。

成员角色权限范围
机构主账号机构最高管理权限；主账号自身不可在成员列表中被随意停用。
管理员机构业务管理与成员管理权限，具体能力由正式权限模型配置。
操作员可执行业务操作，不可进行成员管理或关键规则配置。
只读仅查看授权范围内数据，无写操作权限。

4.4 身份切换

登录后应展示个人身份与全部机构成员身份，按「机构 + 角色」切换。例如：个人用户、广州采购科技集团 · 主账号、彩翼科技有限公司 · 操作员。切换后工作台与权限按当前身份刷新，机构间数据不得互串。

5 注册流程设计

5.1 个人账号注册

个人用户填写真实姓名、身份证号、手机号、密码、短信验证码并同意协议。身份证用于实名核验与查重；提交后免审，自动开通试用，不进入企业/机构注册审核列表。个人账号后续可申请或关联机构身份。

5.1.1 新用户免费体验权益

个人用户注册成功时，平台按当时生效的计费规则，为该平台个人账号初始化新用户免费体验资格。每个符合体验范围的智能体在该用户首次调用时初始化独立的免费次数，按「平台个人账号 + 智能体」累计；次数用完后不重置，后续调用按该智能体已生效的按 Token 或按次计费规则扣费。

规则项说明
适用对象调整后新注册的个人账号；企业/机构申请审核通过后取得机构身份，不重复创建新用户免费权益。
次数与初始化运营端统一配置每个智能体的免费次数；用户注册时获得资格，在首次调用该智能体时初始化对应次数。
扣减与用尽每次成功调用优先扣减 1 次免费体验；用完后不重置，按该智能体当前生效的计费方式扣费。
成本与记录免费调用金额为 0 彩豆，仍记录调用明细；算力成本由平台承担，不计入开发者分成或用户开票金额。
规则变更仅适用于规则调整后新注册用户；已注册用户保留注册时获得的免费次数。

5.2 企业/机构注册

字段规则说明
营业执照企业/机构类型必传；支持图片或 PDF；上传后可 OCR 模拟识别组织名称和统一社会信用代码。
组织名称、统一社会信用代码企业主体信息；信用代码全平台查重。已有主体时带出组织名称，并按新增机构身份处理。
经办人信息真实姓名必填；身份证号按实名与风控规则处理。
手机号全平台唯一，绑定平台个人账号；已有账号不可重复创建登录主体。
密码、短信验证码、协议注册或账号校验所需字段；正式系统的有效期、频控和安全策略由服务端实现。

5.3 提交后处理

分支流程说明
个人用户提交成功 → 自动开通试用 → 以个人身份登录使用；按正式账户规则完成必要初始化。
企业/机构审核通过创建或激活对应机构身份 → 向申请人个人账号增加机构主账号成员关系 → 按机构类型触发账户初始化或金蝶建档等后续能力 → 通知申请人。
企业/机构审核驳回记录驳回原因并通知申请人；申请人修改资料后可重新提交。
原型边界：当前页面中的短信、OCR、审核结果与账户初始化仅用于交互演示；正式上线需接入实名、短信、文件存储、OCR、审核工作流、通知与审计能力。

6 审核状态与成员管理

6.1 企业/机构申请状态机

当前状态动作角色迁移结果 / 附加动作
—提交企业/机构申请个人账号待审核；记录申请人与机构类型。
待审核审核通过运营已激活；向申请人增加机构主账号成员关系，并触发类型对应的后续处理。
待审核驳回（填写原因）运营已驳回；通知申请人并保留原因。
已驳回修改后重新提交个人账号回到待审核。
已激活机构注销—规则预留，本期不实现。

6.2 机构成员管理（本期）

当前原型覆盖成员列表查看、成员搜索、角色调整提示与成员停用提示。运营和机构管理员管理的是机构成员关系，不得删除平台个人身份。

成员关系动作本期范围
查看成员、搜索成员已纳入原型
调整角色、停用成员原型演示，正式系统需权限校验与操作审计
新增/邀请成员、未注册用户激活后续能力；应基于「平台个人账号 + 机构成员关系」建设。
邀请短信、激活链接、Token、待激活状态、设置密码不属于本期原型与需求范围。
移除成员关系规则预留，原型未实现；移除后仍保留该用户的平台个人账号。

6.3 登录与密码找回

登录支持账号密码与手机号验证码两种方式，登录前须勾选用户协议和隐私政策。忘记密码采用「验证手机号 → 输入短信验证码 → 设置新密码 → 返回登录」流程；当前为前端模拟，不保存密码、不发送真实短信。

6.4 通知与待办机制

平台待办用于需要人工处理的事项；站内消息用于向申请人反馈进度与结果；短信仅用于身份校验、密码重置及影响账号使用的关键结果触达。个人用户免审开通，不进入运营审核待办。

触发场景接收方通知方式消息内容 / 后续动作

7 与外部系统衔接

衔接点触发时机说明
实名与短信服务注册、登录、找回密码正式系统校验手机号、验证码有效期和发送频控；静态原型仅模拟 60 秒重发。
营业执照 OCR企业/机构注册上传执照后识别组织名称和统一社会信用代码，需支持用户核对与人工修正。
账户初始化机构审核通过后按机构类型和正式财务规则执行，不能仅以原型展示文案作为实现依据。
金蝶建档开发者机构审核通过后正式接入需保证幂等、失败重试、人工补偿和审计留痕。

8 机构类型可扩展设计

机构类型以数据配置管理，新增类型不应改变平台个人账号唯一性。每种机构类型可配置公开入口、审核要求、所需资质、初始化规则、默认权限模板与工作台入口。

配置项说明
类型名称、编码、入口描述展示与系统内部标识；编码创建后不可修改。
公开入口、审核开关控制是否允许公开申请及是否进入运营审核。
资质与表单规则定义是否需营业执照、实名信息及补充材料。
账户初始化、金蝶建档审核通过后的类型化后续处理。
默认成员角色与权限模板机构身份下的权限初始化；不得绕过个人账号与成员关系模型。

9 验收标准

编号验收标准
AC01公开入口展示个人用户、采购单位、供应商、代理机构、开发者 5 张卡；采购监管不出现在公开入口。
AC02同一统一社会信用代码申请不同机构类型时，系统识别已有企业主体并带出组织名称；本次申请仍独立审核。
AC03同一手机号全平台唯一绑定一个个人账号；再次申请机构身份时关联已有个人账号，不创建跨类型独立登录账号。
AC04个人用户身份证必填、免审开通试用，且不进入企业/机构审核列表；个人账号后续可关联机构身份。
AC05企业/机构申请的待审核、已激活、已驳回状态可按规则迁移；审核通过后为申请人增加对应机构主账号成员关系。
AC05A运营端可创建个人账号，创建前校验手机号和身份证号全平台唯一；账号来源、创建人、创建时间与备注可审计。后台创建的账号不自动获得新用户免费体验权益。
AC06个人账号可切换个人身份和多个机构成员身份；展示信息包含机构与角色，机构资源及权限相互隔离。
AC07本期成员管理支持查看成员、搜索成员、角色调整与停用的原型演示；不将邀请、短信激活和待激活流程列为本期验收能力。
AC08企业/机构注册必须上传营业执照；OCR 识别与信用代码查重能力在正式系统中需可核验、可修正、可审计。
AC09登录支持密码与手机号验证码方式，且须同意协议；忘记密码完成手机号验证、验证码校验、设置新密码和返回登录的原型流程。
AC10验证码、OCR、审核、通知、账户初始化和密码重置在当前静态原型中均明确为模拟；上线前完成对应服务端能力与安全控制。
AC11新注册个人账号对每个智能体获得一次性免费体验次数；按“平台个人账号 + 智能体”独立累计，成功调用优先扣减，用完后不重置并按当前计费规则扣费。
AC12用户端在注册成功、智能体列表、详情与调用反馈中展示免费体验权益；运营端可配置次数并查询初始、已使用、剩余次数与最近使用时间。
