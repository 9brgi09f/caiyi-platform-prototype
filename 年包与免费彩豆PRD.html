年包与免费彩豆一期 PRD

版本：V1.0 · 日期：2026-11-18 · 范围：企业用户端（含个人身份）、平台运营端；财务端、开发者端为配套改造说明。

1. 背景与目标

现有平台只支持单次充值，彩豆永久有效、无赠送。本期新增两类商业化能力：一是年包（买一份得“基础 + 赠送”彩豆，12 个月有效）；二是免费彩豆（个人身份每月赠送 + 每日登录赠送，用于拉新和促活）。同时保留 100 / 500 / 1,000 元三档单次充值和自定义金额，并支持限时充值赠送（默认 1:1）。

成功标准：每笔年包、充值订单都能对应到账彩豆批次；任意时点总余额 = 各类彩豆之和；扣减来源可追溯；开票金额与实付一致；赠送与免费彩豆不开票、不进开发者分账。

2. 已确认范围与待定事项

排除 年包升级、年包退款、年包降级、年包续费折扣、年包转让、单位账户免费彩豆、个人身份岗位菜单、一次性注册赠豆（已确认本期不设，由月度赠豆和每日登录赠豆承担）

与既有文档的关系

  1. 《单位彩豆管理与授权消费产品方案》V1.7：其中“单一来源、直接扣减、彩豆永久有效”被本 PRD 修订——底层按批次分来源扣减，有效期分类管理；界面仍展示一个总余额，详情拆分展示。共有账户、菜单权限、余额预警等其余规则不变。
  2. 《智能体双模式计费与新用户免费体验产品方案》：免费次数规则不变。调用时先判断免费次数（命中则不扣彩豆），次数用尽才进入第 10 节的彩豆扣减。
  3. 运营端原“充值赠送规则”“充值阶梯赠送彩豆”被年包取代；原型中彩豆规则页已移除兑换比例配置和比例修改记录，改为第 6、8、9 节配置项并重新留痕。奖励规则页本期不动，入口保持隐藏。

3. 用户与场景

  1. 单位采购负责人一次性购买标准版年包，全体成员共用年包彩豆；年中业务量增加，可再购一份年包（单独计算有效期，先到期先用），或单次充值补足。
  2. 个人用户每月第一次登录得 50 彩豆月度赠豆，之后每天登录得 5 彩豆，登录赠豆月内累计到 50 后不再发放；当月没用完的免费彩豆月底清零，下月重新发放。
  3. 单位财务需要开票：年包按实付金额开一张；赠送彩豆不进发票。
  4. 个人用户通过“发票管理”给自己的充值或消费申请开票，并在消费记录中查看开票状态。
  5. 运营新增“旗舰版”年包、调整赠送比例或停售旧档位，只影响之后的新订单，已购年包按购买时的条件执行。

4. 角色权限

主体 权限
单位主账号 查看单位彩豆余额与年包；有“账户充值”菜单权限即可购买年包、单次充值；开票按“发票管理”权限
单位子账号 按岗位菜单权限；无“账户充值”看不到入口、不可购买；无“彩豆管理”不可看余额明细；有智能体市场权限即可消费共有彩豆
个人用户 个人用户自行购买年包、充值、消费、查看免费彩豆并申请开票，发票管理仅展示当前个人账户的数据
平台运营 在“规则设置 → 彩豆规则”配置年包、单次充值、免费彩豆；保存留痕
财务 通过充值记录、对账查看年包订单；本期无新增操作权限

同一手机号的个人身份与单位身份，余额、年包、免费彩豆、记录和发票互相隔离，不迁移、不合并。数据隔离、菜单权限、状态机与金额校验必须由服务端完成。

5. 彩豆类型与账户模型

每个账户（单位账户或个人账户）的余额由三类彩豆批次组成：

类型 来源 有效期 开票 开发者分账
免费彩豆 个人月度赠豆、每日登录赠豆 当月有效，月底清零 不开票 不分账
年包彩豆 年包购买（基础 + 赠送） 年包有效期内，到期清零 购买订单按实付开票；其消费按本金分摊金额开消费发票，赠送部分不开票 按本金分摊金额（第 12 节）
充值彩豆 单次充值（含充值赠送） 长期有效 充值订单按实付开票，赠送不开票；其消费按本金分摊金额开消费发票 按本金分摊金额，无赠送时为全额
  • 总余额 = 免费 + 年包 + 充值，企业身份没有免费彩豆。
  • 年包彩豆按“年包份”建批次：每份记录购买日、到期日、总彩豆、剩余彩豆、实付。
  • 免费彩豆按自然月建批次；充值彩豆按充值订单建批次，每批记录实付、充值彩豆、赠送彩豆、未分摊实付和未使用彩豆。无赠送的历史充值可合并为一个长期批次（未分摊实付等于未使用彩豆）。充值彩豆内部按到账先后扣减。
  • 展示上充值赠送仍归入“充值彩豆”，旁注累计获赠数量，不新增第四类彩豆。
  • 展示：余额条按三类着色，每类标注到期日；0 余额的类型在企业身份下不展示。

6. 年包规则

6.1 运营配置

配置项 规则
年包名称 必填，不超过 10 个字，不重复
价格 正整数，元 / 年
赠送比例 0–100 的整数 %；赠送彩豆 = 价格 × 比例，四舍五入取整；年度总彩豆 = 价格 + 赠送彩豆
在售状态 在售才在用户端展示和可购买；在售最多 6 个
有效期 全局统一，1–36 个月
删除 没有任何订单的年包可删除；已产生订单的只能停售
生效 保存即生效，仅影响之后的新订单；已购年包保留购买时快照
留痕 记录操作人、时间、修改项及修改前后值（原型仅展示修改后）

6.2 默认预置

6.3 购买与有效期

  1. 用户在“账户充值”选择年包，进入确认页，勾选《彩豆规则》后支付；支付方式沿用现有在线支付与机构对公账户（个人身份仅个人支付）。
  2. 订单锁定下单时的价格与比例；支付时目标年包已停售则拒绝并提示重新选择。
  3. 支付成功后一次性生成年包批次：基础彩豆 = 价格，赠送彩豆 = 比例折算，同时到账；写入账本流水并生成充值记录（订单类型“年包”）。
  4. 有效期：自购买日起 N 个月，到期日 = 购买日 + N 个月 − 1 天（目标月无该日取当月最后一日），到期日 23:59:59 前可用。例：2026-09-01 购买，到期 2027-08-31。
  5. 可重复购买，每份年包独立计算有效期；多份并存时先到期的先扣。
  6. 到期次日 00:00 未用完的年包彩豆清零，生成“到期清零”流水，保留剩余数量供对账。不支持退款、延期或转让。

7. 年包升级（本期不做）

  1. 2026-11-25 确认本期不做年包升级：用户端不展示升级入口，没有升级订单，运营端不展示升级路径。
  2. 已购年包的用户需要更多彩豆时，可再购一份年包（各自计有效期，扣减先到期先用）或单次充值。
  3. 原型中升级的测算与下单代码保留但关闭（user/bean-plan.js 中 UPGRADE_ENABLED = false）；后续如启动，需重新评审补差价、补发彩豆、有效期与开票口径。本金分摊算法可把补差价与补发彩豆并入原年包批次，无需改动。

8. 单次充值

  1. 三档 100 / 500 / 1,000 元可选；档位由运营配置，须大于 0 且由低到高。
  2. 自定义金额为 10–10,000 元的整数，范围由运营配置；非整数或越界时提示，不允许提交。
  3. 长期有效，到账进入充值彩豆。
  4. 自定义金额大于等于最低价在售年包价格，且该年包总彩豆多于同金额充值（含赠送）时，提示“同样支付 X 元购买 XX 年包，可多得 Y 彩豆”，引导看年包，不拦截。充值赠送比例较高时不提示。

8.1 充值赠送（限时活动）

  1. 运营在“彩豆规则 → 充值赠送”配置开关、赠送比例（1–200% 整数，默认 100%）、活动开始与结束日期（默认 2026-11-15 至 2026-12-31）。
  2. 赠送彩豆 = 充值金额 × 赠送比例，四舍五入取整；档位与自定义金额使用同一比例。默认配置下充 100 得 200、充 500 得 1,000、充 1,000 得 2,000。
  3. 企业与个人身份均可享受，每次充值都送，不限首充、不限次数。
  4. 是否赠送以支付成功时间为准：开关打开且在起止日期内（含当天）才赠送；未开始、已结束或关闭时按原价到账，不补发。
  5. 赠送彩豆与充值彩豆一同到账、同为长期有效；不开票、不给开发者分账、不计渠道佣金。
  6. 保存校验：比例越界、缺少日期、结束日期早于开始日期时拦截。赠送比例不低于在售年包最低赠送比例时，提示“年包将失去吸引力，请确认这是限时活动”，不拦截。
  7. 用户端：活动期内充值页显示“限时充值 1:1 赠送”横幅和起止日期，档位卡片显示“送 X”和到账彩豆；自定义金额实时显示到账数；确认页列出“充值 X + 赠送 Y”和开票金额；支付结果、充值记录、变动明细显示赠送数量；规则弹窗按当前活动状态生成。
  8. 风险提示：默认 100% 赠送高于全部年包，活动期内年包吸引力下降；赠送部分不分账，开发者每彩豆收入减半；赠送部分的算力成本由平台承担（见 Q4）。

9. 免费彩豆

  1. 仅个人身份，包含两项，可分别开关，数量由运营配置。两项是个人注册用户的基础福利，本期不另设一次性注册赠豆，与新用户免费体验次数并存、互不冲突。
  2. 月度赠豆：每个自然月赠送 50 彩豆，在当月首次登录时到账；注册当月首次进入即到账。当月未登录的账号不发放，不补发。
  3. 每日登录赠豆：每日首次登录赠送 5 彩豆，每月上限 50 彩豆。
  4. 月度赠豆同一账号同一自然月只发一次，服务端幂等，不计入登录赠豆上限。登录赠豆的“每日”按自然日，同一账号同一天只发一次，服务端幂等；本月可领数 = 上限 − 当月已领，最后一次不足 5 时按剩余发放，领满后不再发放。
  5. 企业身份登录不赠豆，单位账户不发放月度赠豆；个人账号切换到企业身份不触发，也不影响企业账户。
  6. 免费彩豆当月有效，月底 23:59:59 后未用部分清零，生成“到期清零”流水。
  7. 可用于全部智能体；持有年包的个人同样享有；不开票；消费不给开发者分账，算力成本按现有免费体验口径由平台承担（待确认）。
  8. 用户端提示：个人身份首次进入页面时轻提示到账数量。当月首次登录合并提示“本月赠送 50 彩豆 + 今日登录赠送 5 彩豆”，其余日期提示“今日登录赠送 5 彩豆 · 本月 n / 50，当月有效”。概览和彩豆管理展示本月月度赠豆与登录赠豆进度，变动明细分别记为“月度赠豆”“每日登录赠豆”。

10. 扣减规则

  1. 调用前先判断“新用户免费体验次数”：命中则不扣彩豆；否则进入彩豆扣减。
  2. 扣减顺序：个人 免费彩豆 → 年包彩豆 → 充值彩豆；企业 年包彩豆 → 充值彩豆。同类内部先到期先扣。
  3. 一笔消费可跨来源拆分，各来源分项之和等于消费总额，消费记录保留分项与对应批次。
  4. 余额以三类总和判断是否足够，不足时在调用前拦截并引导充值（既有规则）。
  5. 调用失败不扣彩豆，不产生来源分项，保留失败记录。
  6. 扣减在事务内按批次条件更新，保证批次余额不为负、同一请求只扣一次（以请求 ID 幂等）。
  7. 已过期批次不参与扣减；到期清零与扣减并发时，以服务端时间点为准。

11. 开票规则

个人用户可在个人身份下为本人充值订单与符合条件的消费申请开票，并查看申请详情和开票状态。个人与单位使用相同的金额计算规则。

订单 / 消费 开票金额 说明
年包购买 实付金额 赠送彩豆不开票；发票类型沿用预付卡发票（待财务确认）
单次充值 实付金额 含充值赠送时，赠送彩豆不开票
消费（含年包彩豆） 年包彩豆部分的本金分摊金额 按第 12.1 节逐笔分摊，金额写入消费单，之后清零不改变。例：入门版已消费 1,180 彩豆后消费 1,045.6 彩豆，可开 1,045.6 × 5,072.31 ÷ 6,594 = 804.31 元
消费（含充值彩豆） 充值彩豆部分的本金分摊金额 无赠送批次开票金额等于彩豆数量。例：充 100 得 200，消费其中 110 彩豆可开 55 元
消费（含免费彩豆） 免费部分不计入 免费彩豆不开票
  • 个人开票默认使用个人抬头，纳税人识别号选填。用户可添加企业抬头，使用企业抬头时须填写纳税人识别号。常用抬头按账户独立保存。
  • 申请提交即占用订单或消费单的开票资格，订单状态变“开票中”，同一订单不可重复申请；驳回后释放。
  • 充值开票列表增加“订单类型”，年包订单旁提示“到账 X 彩豆，其中赠送 Y 不开票”。
  • 一笔消费跨年包与充值、或跨多个批次时，按批次分别折算后相加，按整笔申请；消费详情逐批展示“彩豆 × 未分摊实付 ÷ 未使用彩豆 = 金额”。
  • 消费开票列表展示消费金额与可开票金额，纳入含年包或充值彩豆且仍待开票的消费；仅用免费彩豆的消费不可开票。
  • 年包订单与单次充值一样，购买时可开充值发票，消费时可再开消费发票，两者关系沿用现有充值发票与消费发票的口径，本期不改动。

12. 开发者分账与财务对账

12.1 本金分摊算法

消费开票金额与开发者分账基数使用同一个“本金分摊金额”，按批次逐笔计算，保证每个批次用完时分摊合计正好等于实付，不因四舍五入产生差额。

  1. 批次：每份年包、每笔充值各为一个批次，记录“未分摊实付”（单位分，初始 = 实付）和“未使用彩豆”（初始 = 到账彩豆，含赠送）。无赠送的历史充值可合并为一个批次。
  2. 每笔消费从某批次扣 x 彩豆时：分摊金额 = x × 未分摊实付 ÷ 未使用彩豆，四舍五入到分；然后未分摊实付减去该金额、未使用彩豆减去 x。
  3. 扣 x 后批次彩豆用完时，分摊金额直接取全部未分摊实付，吸收此前的尾差。
  4. 跨来源或跨批次的消费，按扣减顺序在各批次分别计算后相加；分摊金额写入消费扣减明细，开票与分账都读这个值，不重复计算。
  5. 到期清零：年包到期时剩余的未分摊实付不再开消费发票、不分账，记为该年包的“清零金额”，供财务处理（Q2）。
  6. 不存储四舍五入后的系数；单价比例只用于展示估算。
场景 计算 结果
入门版逐笔 1 彩豆用完 7,774 彩豆 每笔 0.76 或 0.77 元，最后一笔吸收尾差 合计 5,980.00 元；若按固定系数逐笔四舍五入会多 5.98 元
1:1 赠送充值 100 元得 200 彩豆 消费 110 彩豆分摊 55 元，剩余 90 彩豆分摊 45 元 合计 100.00 元

开发者分账：沿用现有“结算收入按实付现金基数计算”的口径，基数 = 消费单的本金分摊金额。

消耗的彩豆 分账基数 示例
充值彩豆 本金分摊金额（无赠送时等于彩豆数） 无赠送消耗 100 彩豆，基数 100 元；1:1 赠送批次消耗 100 彩豆，基数约 50 元
年包彩豆 本金分摊金额 入门版首笔消耗 320 彩豆，基数 320 × 5,980 ÷ 7,774 = 246.15 元
免费彩豆 0 不分账

开发者结算详情补充说明“免费彩豆与赠送彩豆（含年包赠送和充值赠送）部分不参与分账”。算力成本口径本期不变，赠送与免费彩豆消费对应的算力成本承担方待业务确认（建议平台承担）。

财务对账

  1. 总余额恒等式：期末总彩豆 = 期初总彩豆 + 充值到账（含充值赠送）+ 年包到账 + 免费彩豆赠送 − 消费 − 到期清零。
  2. 分类恒等式：免费、年包、充值三类各自按同样口径对平；年包按份对平。
  3. 订单维度：每笔年包 / 充值订单保留实付、基础彩豆、赠送彩豆、有效期，批次保留未分摊实付与未使用彩豆，充值订单另存活动规则快照（比例、起止日期）；赠送与免费彩豆单独记账，具体科目由财务确认。
  4. 批次恒等式：实付 = 已分摊金额合计 + 未分摊实付（+ 清零金额）。到期清零的会计处理（是否确认收入）待财务确认；系统保留清零明细与清零金额供核算。
  5. 渠道佣金按实付金额计算，赠送彩豆不计入（默认口径）。

14. 数据与异常

主要数据：订单（订单号、类型、账户、实付、基础、赠送、年包 ID、价格与比例快照、支付状态、开票状态）；年包实例（年包 ID、档位快照、实付、年度总彩豆、购买日、到期日）；彩豆批次（批次 ID、账户、类型、来源订单、总量、剩余、到期时间、实付、未分摊实付（分）、清零金额）；账本流水（业务唯一键、批次、变动类型、变动前后值）；消费扣减明细（消费单、批次、数量、本金分摊金额（分），开票与分账共用）；运营配置版本（含前后值、操作人、时间）。

金额与精度：金额使用分，彩豆保留两位小数（按百分之一整数存储），禁止浮点累计；年度总彩豆与赠送彩豆为整数。本金分摊按第 12.1 节逐笔取整到分并扣减余额，同一批次的分摊在事务内串行，保证余额不被并发重复使用。

异常策略

  1. 重复提交、重复支付回调：同一订单只入账一次。
  2. 购买时年包已停售：拒绝并提示重新选择，不扣款。
  3. 支付成功但入账失败：订单保持“已支付待入账”并自动重试，不重复到账、不丢单。
  4. 运营修改配置：只影响之后的新订单；未支付订单按下单快照，支付时校验在售状态。
  5. 年包到期与扣减并发：以服务端时间为准，到期后不可扣。
  6. 存储或提交失败：保留表单并明确提示，允许重试，不误报成功。
  7. 开票与消费并发：同一订单或消费单的开票占用必须在服务端加锁，不能仅靠按钮禁用。

实施顺序：口径定稿（第 17 节）→ 批次账本与扣减 → 年包购买 → 单次充值与免费彩豆 → 开票与分账联动 → 配套页面与通知 → 边界用例验收。
